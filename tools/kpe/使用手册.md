# kpe 使用手册

> 一句话：**装不装都能用；最稳的调用方式是 `python -m kpe`**（Windows 上
> 控制台入口 `kpe.exe` 可能被应用程序控制策略拦，见 §2 末尾）。

## 1. 它是什么

`kpe` 是一个独立的命令行工具：把 PDF / Markdown / 纯文本切成结构块，逐块调用
**任意 OpenAI 兼容模型**抽知识点，产出 `chunks.jsonl` / `points.jsonl` /
`review.md` / `stats.json`。它不依赖宿主项目，也不写数据库。

四个子命令：`chunks`（分块，免费）、`extract`（抽点，花钱）、
`review`（复核稿）、`stats`（汇总）。

## 2. 安装

### 方式 A：不安装（推荐，零副作用）

```powershell
cd <仓库目录>
$env:PYTHONPATH = "<仓库目录>"
uv run --with pdfplumber python -m kpe --version      # 0.1.0
```

优点：不动环境、换机器只改路径。缺点：每条命令都要先设 `PYTHONPATH`
（可写进脚本开头）。

### 方式 B：装进当前解释器

```powershell
cd <仓库目录>
pip install .                    # 或 uv pip install .
python -m kpe --version          # 0.1.0
```

之后任意目录都能 `python -m kpe ...`。

### 方式 C：只给这个工具一个独立 venv

```powershell
uv venv D:\tools\kpe-venv
uv pip install --python D:\tools\kpe-venv\Scripts\python.exe pdfplumber
$env:PYTHONPATH = "<仓库目录>"
D:\tools\kpe-venv\Scripts\python.exe -m kpe --version
```

任何 Python ≥ 3.10、装了 `pdfplumber`、且 `PYTHONPATH` 指向本仓库目录的进程，
都能 `python -m kpe` 直接跑，无需安装。

### 关于 `kpe` 入口与 pipx / `uv tool`

`pip install .`、`pipx install .`、`uv tool install .` 都会生成 `kpe.exe`。
若机器上被应用控制策略拦（报 `Failed to spawn: kpe` / `os error 4551`），
退回 `python -m kpe`，功能完全一致——**不要**为了排障去改系统策略。

## 3. 验证

```powershell
python -m kpe --version        # 0.1.0
python -m kpe --help           # chunks / extract / review / stats
python -m kpe chunks examples\sample.md --out temp\smoke
```

最后一条零成本，能验证分块链路与产物格式。

## 4. 四个命令

### 4.1 `chunks`：只分块（不花钱，先跑这个）

```powershell
python -m kpe chunks "<输入文件>" --out <输出目录>
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `input` | 必填 | `.pdf` / `.md` / `.txt` |
| `--out` | 必填 | 产物目录，不存在会创建 |
| `--book-title` | 文件名 | 写进 manifest 的书名 |
| `--target-chars` | 6000 | 每块目标字数 |
| `--overlap` | 600 | 超长节切分时的重叠字数 |
| `--max-chars` | 8000 | 单节超过它就切 |
| `--keep-front` | 关 | 保留前言/引言（默认跳过） |

输出会打印：页数、目录条数、页偏移、块数、总字符、前后几块的路径。
**先确认这些数字合理**，再进入付费步骤。

### 4.2 `extract`：逐块抽知识点（花钱）

```powershell
python -m kpe extract <out目录> --base-url <接口地址> --model <模型名> --api-key-env <环境变量名>
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `out` | 必填 | `chunks` 生成的目录 |
| `--base-url` | 必填 | 如 `https://api.siliconflow.cn/v1` |
| `--model` | 必填 | 如 `deepseek-ai/DeepSeek-V4.1-Flash` |
| `--api-key-env` | `KNOWATLAS_LLM_API_KEY` | 从哪个**环境变量名**读 key |
| `--thinking` | `off` | `off` / `on` / `omit`；DeepSeek 用 off，混元类用 omit |
| `--workers` | 4 | 并发；免费模型/限流严重时用 2 |
| `--temperature` | 0.2 | 抽取建议低 |
| `--timeout` | 180 | 单次请求秒数 |
| `--max-tokens` | 0 | 0 = 不传 |
| `--limit` | 0 | 只跑前 N 块（试跑用） |
| `--chapter` | 无 | 只跑路径含该子串的块，可多次 |
| `--retry-failed` | 关 | 只重跑失败块 |
| `--redo` | 关 | 忽略已完成记录，全部重跑 |
| `--price-in/--price-out` | 0 | 元/百万 token，用于打印成本 |

每 5 块打印一次进度；结束打印点数、拒点、重复、失败、quote 命中、token、
耗时、估算成本。

### 4.3 `review`：生成复核稿

```powershell
python -m kpe review <out目录> [--dest 路径] [--limit N] [--with-sections]
```

默认写 `<out>/review.md`：只按**章**分组，每点带 quote；要溯源时加
`--with-sections` 恢复每节路径与页码小标题。

### 4.4 `stats`：看汇总

```powershell
python -m kpe stats <out目录>
```

打印 `manifest.json` + `current`（按 `points.jsonl` / `done.jsonl` / `cache/`
现算的总点数、模型、token、拒点）+ `last_run`（最近一次 extract 的
`stats.json`）。分多次跑，`current.points` 仍是全书总数。

## 5. 完整示例

### 5.1 DeepSeek（关思考，最常用）

```powershell
cd <仓库目录>
$env:PYTHONPATH = "<仓库目录>"
$env:KNOWATLAS_LLM_API_KEY = "<你的 key>"

python -m kpe chunks "<你的书>.pdf" --out temp\book

python -m kpe extract temp\book `
  --base-url https://api.siliconflow.cn/v1 `
  --model deepseek-ai/DeepSeek-V4.1-Flash `
  --api-key-env KNOWATLAS_LLM_API_KEY `
  --thinking off --workers 4 --price-in 2 --price-out 8

python -m kpe review temp\book
python -m kpe stats  temp\book
```

### 5.2 换一家模型（腾讯混元等）

所有 OpenAI 兼容服务只换三个参数；若服务不认 `thinking` 字段，用 `--thinking omit`：

```powershell
$env:HUNYUAN_API_KEY = "<你的 key>"

# 复用同一份块，另建目录，保证结果可比
New-Item -ItemType Directory temp\book-hy -Force | Out-Null
Copy-Item temp\book\chunks.jsonl, temp\book\manifest.json temp\book-hy\

python -m kpe extract temp\book-hy `
  --base-url https://api.hunyuan.cloud.tencent.com/v1 `
  --model "<以服务商文档为准>" `
  --api-key-env HUNYUAN_API_KEY `
  --thinking omit --workers 2 --price-in <输入价> --price-out <输出价>
```

### 5.3 先试 3 块（最省钱）

```powershell
python -m kpe extract temp\book ... --limit 3
```

3 块约几分钱，用来确认 key、网络、JSON 都通。

## 6. 在别的 Agent / 自动化里调用

只要能执行 shell 命令即可。注意三件事：**工作目录**、**PYTHONPATH**、**key 注入**。

```powershell
cd <仓库目录>
$env:PYTHONPATH = "<仓库目录>"
$env:LLM_KEY = "..."
python -m kpe extract temp\book --base-url ... --model ... --api-key-env LLM_KEY --thinking omit --workers 2
```

```bat
cd /d <仓库目录>
set PYTHONPATH=<仓库目录>
set LLM_KEY=...
python -m kpe extract temp\book --base-url ... --model ... --api-key-env LLM_KEY --thinking omit --workers 2
```

```bash
cd <仓库目录>
export PYTHONPATH=<仓库目录>
export LLM_KEY=...
python -m kpe extract temp/book --base-url ... --model ... --api-key-env LLM_KEY --thinking omit --workers 2
```

**不要把 key 直接写进命令行**：让调用方在启动进程时注入环境变量。

## 7. 断点续跑与重跑

- 每次成功调用写 `cache/<chunk_id>.json`；成功处理的块记进 `done.jsonl`。
- 再跑同一条 `extract`：已完成的块直接跳过，只补新块/失败块。
- 全重跑：加 `--redo`（会重新调模型，`points.jsonl` 按去重追加）。
- 只补失败块：加 `--retry-failed`。
- 只跑某几章：`--chapter "第 2 章" --chapter "第 7 章"`（子串匹配）。
- 试跑：`--limit 5`。

## 8. 产物说明

| 文件 | 用途 |
|---|---|
| `manifest.json` | 书元数据、目录条数、偏移、参数、块数 |
| `chunks.jsonl` | 每块：章节路径、页码、字数、正文 |
| `cache/` | 原始响应 + usage，断点续跑 |
| `points.jsonl` | 点：章节、页码、text、quote、quote_ok、模型 |
| `rejected.jsonl` | 被闸门拒的点 + 原因（调 prompt 用） |
| `failed.jsonl` | 失败块（`--retry-failed`） |
| `stats.json` | 本次运行的统计 |
| `review.md` | 人工复核稿 |

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `No module named kpe` | 没设 `PYTHONPATH` 也没安装；用方式 A 或 B |
| `Failed to spawn: kpe` / `os error 4551` | 控制台 exe 被应用控制策略拦；改用 `python -m kpe` |
| `No module named pdfplumber` | `pip install pdfplumber` 或 `uv run --with pdfplumber ...` |
| `环境变量 XXX 为空` | key 没注入当前进程；同一条命令里先设置再跑 |
| HTTP 401 | key 错/过期/没余额 |
| HTTP 429 | 限流；`--workers 2`，等一会再跑 |
| 连不上 base_url | 网络/代理；换端点或设代理环境变量 |
| `没有待处理的块（都已 done；要重跑加 --redo）` | 正常；加 `--redo` 或换目录 |
| 分块 `目录条=0` | PDF 没有可解析目录，已退化为窗口分块 |
| 中文乱码 | `chcp 65001` + `$env:PYTHONIOENCODING="utf-8"` |
| 文件名有空格 | 整条路径加引号 |

## 10. 成本与时间参考

《AI-Agents-in-Depth》实测（DeepSeek-V4.1-Flash，关思考，4 并发）：

- 96 块 / 44 万字 → **571 点**，quote 570/571；
- **≈ ¥0.85**，**130 秒**；
- 免费 8B 模型：¥0，但约 6–10 秒/块，96 块串行约 15–20 分钟；
- 其他模型按服务商单价，`--price-in/--price-out` 传进去就会打印成本。
