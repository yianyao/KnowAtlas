# 示例书：长文知识点抽取的最小样例

这是 `examples/sample.md`，用来零成本验证 `kpe chunks` 能不能把你的文件
切成结构合理的块。它只有几十行，几秒就能跑完，不需要任何 API key。

## 第一章 为什么要抽取知识点

一本书动辄几十万字，直接塞给模型既贵又容易丢细节。更稳的做法是先把书切成
结构块，再逐块抽「能脱离原文独立读懂」的知识点，最后人工复核。

知识点要自包含：读者只看这一条，不看原书，也能明白它在说什么。凡是主语缺失、
代词开头、结论悬空的句子，都不算合格的点。

## 第二章 三步流程

第一步分块：优先用 PDF 目录页拿到章节路径与印刷页码，再按章合并到约六千字。
没有目录就退化为标题或固定窗口。

第二步抽取：每块要求模型给出若干条点，并给出逐字引文作为出处凭证。引文必须
能在原文里找到，否则这条点作废。

第三步复核：把点按章汇总成 Markdown，人工扫一遍，把不合格的删掉或改写。

## 第三章 成本与质量

质量与成本是一对矛盾。用强模型、开思考，点更准但更贵；用弱模型，便宜但需要
更多人工筛选。实践上先用少量块试跑，比较两三家的产出，再决定全书用哪个。

一个可操作的经验：先跑三块，看有没有明显的空话、重复、脱离上下文；如果三块
都合格，再全量。

## 第四章 结语

工具只负责把结构化的初稿做出来，判断哪些点值得留下，仍然要人来做。
