# 模块地图（KnowAtlas 现状清点，2026-10-27）

> 用途：回答「现在到底有什么、在哪、谁依赖谁」。用于规划重构、判断哪些该独立成仓库。
> 口径：只统计 `src/knowatlas`（90 个 .py / **16,559** 非空行）+ `tests`（687 个测试函数，
> pytest 实收 **727** 例，含参数化）+ `tools/` + 真库现状。数据由 `temp/inventory_20261027.py`
> 只读清点生成，重跑可刷新。
>
> 组织方式：**按能力域（类别）而不是按目录**。一个能力域会横跨 `adapters/` `pipeline/`
> `semantic/` `web/` 多个目录——目录是分层，类别才是「一件事」。

## 0. 总览

| 类别 | 一句话 | 规模（非空行） | 稳定性 |
|---|---|---|---|
| A 契约与数据层 | 唯一事实来源 + 只读查询 + 迁移 | ~3,600 | 🔒 冻结区（改动必须工单 + canary） |
| B 采集与入库 | 各源 → 统一条目 → 抓正文 → 激活 | ~3,300 | 🟡 演进中（刚加自动分流） |
| C 语义与分类 | 先验→规则→embedding/LLM 三级 | ~2,300 | 🟡 演进中 |
| D 知识点（抽取/分诊/勘误/老化） | 点的一生 | ~2,400 | 🟢 最活跃 |
| E 质量与治理 | 清洗、去重、时效、体检、回收 | ~1,500 | 🟢 稳定 |
| F 编排与任务 | 把上面串成可重复的作业 | ~1,900 | 🟡 演进中（R18 新增巡检） |
| G 应用层（Web/桌面） | 浏览器里的全部界面与接口 | ~2,300 | 🟡 演进中 |
| H 独立工具与旁路 | 可单独安装/运行的外部件 | 仓库外 | 🟢 已分离 |

依赖方向（硬约束，逆向即 bug）：

```
G 应用层 ──▶ F 编排 ──▶ B/C/D/E 领域 ──▶ A 数据层（唯一 sqlite3）
                     └─▶ H 独立工具（只经文件/子进程，不 import 主库）
```

## A 契约与数据层（冻结区）

| 模块 | 职责 | 关键文件 |
|---|---|---|
| 数据层 | 所有读写、事务、视图、游标；唯一建连处 | `datalayer/core.py`（组合/连接/事务/迁移，113 行）+ 10 个 mixin：`entries` 579 / `graph` 726 / `points` 518 / `views` 333 / `threads` 323 / `categories` 302 / `search` 264 / `vectors` 112 / `content` 107 / `ops` 143，共享常量在 `_common.py` 90；`db.py` 只是 12 行兼容 façade（2026-10-28 拆自 3,462 行单文件） |
| DDL/迁移 | 10 个迁移、`user_version`、canary 摘要 | `datalayer/schema.py`、`datalayer/migrations/001–010` |
| 模型 | 全部 dataclass 与枚举（Entry/Category/PointHit/…） | `models.py` |
| 标识 | entry_id / canonical_url / content_hash / 文本规范化 | `ids.py` |
| 错误 | 分类错误 + `entry_id` + `hint` | `errors.py` |
| 配置 | TOML + `KNOWATLAS_*` 环境变量 + 键集校验（canary 指纹） | `config.py`（202 行） |
| 日志 | 结构化 JSON 行，禁凭证/正文 | `logging_setup.py` |

**表（16）**：`entries` `entry_locators` `categories` `category_parents` `entry_categories`
`content_store` `points` `point_sources` `point_vectors` `entry_vectors` `runs` `task_log`
`threads` `thread_items` `conv_messages` `regress_cases`。

**真库现状**：entries 368（active 76 / pending 132 / rejected 78 / archived 82；bookmark 191 /
folder 148 / expand 20 / emmx 9）；points 4,965（opinion 2,016 / hard 1,579 / unjudgeable 914 /
无 413 / dupe 43）；分类仅 7 个（一级 3 个：人工智能 / 技术开发 / 文学创作）；点溯源 1:1。

**契约纪律**：字段/scheme/状态/表结构/`CONFIG_SCHEMA_KEYS` 任一变更 → 工单 + canary 升版；
`datalayer/` 之外不得出现 `INSERT/UPDATE/DELETE` 与 `sqlite3.connect`。

## B 采集与入库

| 模块 | 职责 | 关键文件 |
|---|---|---|
| 源适配器（10） | 各源 → 统一 `Entry`，不抓不分类 | `adapters/{bookmark,folder,emmx,maildir,opml,session,dbfile,manual}.py` |
| 抓取器（7） | 按 scheme 抓正文（https/file/office/pdf/emmx） | `fetchers/{http_simple,http_deepseek,file_reader,office_legacy,pdf_fast,base}.py` |
| 同步编排 | 遍历源 → upsert → 抓取 → 分类 → 归档/舍弃 | `pipeline/sync/`（6 文件：`__init__` 276 / `enrich` 273 / `fetch` 155 / `store` 108 / `_common` 42 / `flags` 40） |
| 手动入库 | `kadd` 全链路（URL → 条目 → 正文 → 分类） | `pipeline/kadd.py` |
| 书签扩散 | 从种子链接爬相关页 | `pipeline/expand.py`（385 行） |
| **入库即处理** | 待审激活 → 分流 → 抓/抽 → 老化 | `pipeline/ingest.py`、`ingest_router.py`、`web/worker.py` |
| 长文旁路 | KPE 子进程 + 产物导入 | `pipeline/kpe_runner.py`、`kpe_import.py` |

入口：`ksync`（含 `--source/--full/--entry/--fetch-limit/--purge-source` 等 16 个开关）、
`kadd`、`kauto`、serve 巡检线程。

## C 语义与分类

| 模块 | 职责 | 关键文件 |
|---|---|---|
| 三级流水线 | L1 先验（路径前缀）→ L2 规则（关键词/域名）→ L3 LLM | `semantic/priors.py`、`rules.py`、`tasks/classify_coarse.py` |
| LLM 分类 | 标题+域名+路径 → 分类路径（自评置信度） | `tasks/classify_deep.py` |
| 命名 | 网页原标题 → 知识化短名 | `semantic/naming.py` |
| 关键词 | jieba tf-idf；词云与主题共用 | `tasks/tag_keywords.py`、`semantic/keywords.py` |
| 向量 | 本地/远程 embedding、混合检索、聚类 | `semantic/embed.py`、`pipeline/embed_index.py`（466 行） |
| LLM 客户端 | OpenAI 兼容 Chat + JSON 容错 + 并发池 | `semantic/llm.py` |

## D 知识点（点的一生）

| 阶段 | 模块 | 说明 |
|---|---|---|
| 抽取 | `pipeline/points.py`（435）、`tasks/point_extract.py`（2.2.0） | 形态判定（整体/切分）、分块、阈值、自洽性闸门 |
| 闸门 | `pipeline/point_gate.py` | 裸名词/残缺步骤/截断 → 不落库 |
| 分诊 | `pipeline/triage.py`、`tasks/point_triage.py` | hard / opinion / unjudgeable（勘误与老化只吃 hard） |
| 勘误 | `pipeline/errata_points.py`、`tasks/point_errata.py` | 事实核查 + 原因码；L1 确定性 + L2 LLM |
| 老化 | `pipeline/aging.py`、`lifecycle.py`、`domain_gate.py`、`semantic/eol.py` | 条目级被动复核 + 点级主动扫描（版本 EOL / 技术退场）+ 域闸门 |
| 聚合 | `pipeline/graph_topics.py`、`tasks/topic_recall.py` | 关系图主题节点、多路召回 |
| 合成 | `tasks/synthesize.py`、`tasks/point_explain.py` | 勾选点 → 方案文档；单点释疑 |
| 读写面 | `datalayer/points.py`·`search.py` 的 `put_point/points_of_kind/get_point_hit/…` | 消费面过滤 `aging_flag != 'stale'` |

## E 质量与治理

| 模块 | 职责 | 文件 |
|---|---|---|
| 清洗 | 页码/页眉/目录点线/推广/导航 → 只留知识 | `pipeline/clean.py`（365） |
| 去重 | 同 URL / 同内容合并，共享点保留 | `pipeline/dedupe.py` |
| 时效 | 年份/日期信号 → suspect/stale（零费用） | `semantic/freshness.py` |
| 价值守卫 | 首页/列表页/乱码 → not_knowledge | `semantic/value_guard.py` |
| 链接体检 | 死链标记与内容回收 | `pipeline/health.py`、`kcheck --gc-content` |
| 回归集 | 人工校正样例 → few-shot | `pipeline/regress.py`、`regress_cases` 表 |

## 重构视角：哪里最该动

| 判据 | 命中 | 风险 | 建议 |
|---|---|---|---|
| 单文件 > 1,500 行且改动频繁 | **已清零**（2026-10-28 路线 A）：`web/api.py` 1,952 → 7 routers、`datalayer/db.py` 3,462 → 10 mixin + `core.py` | — | 当前最大：`datalayer/graph.py` 726、`adapters/emmx.py` 600、`web/routers/entries.py` 600 |
| 单文件 > 700 行且多职责 | 已拆：`pipeline/sync/` 6 文件、`cli/` 8 文件、`web/routers/` 7 域 | 低 | 下一个候选：`adapters/emmx.py` 600、`pipeline/embed_index.py` 497 |
| 子进程 + `PYTHONPATH` 注入 | `kpe_runner.py` | 低 | 依赖声明化（可选 extra + 版本探测 + 明确错误码），后期再考虑 HTTP 化 |
| 阈值/常量散落 | `points.py`、`aging.py`、`clean.py` 内常量 | 低 | 逐步收进 `[points]/[aging]/[clean]` 配置（已有先例） |
| 文档膨胀 | `docs/design/` 40+ 篇、两份总纲 | 低 | 建索引页，把「已落地」的工单归档到 `docs/design/archive/` |
| 测试与模块一一对应 | 69 个测试文件 / 687 函数 | — | 拆文件时同步拆测试，别让大文件测试变成回归瓶颈 |
