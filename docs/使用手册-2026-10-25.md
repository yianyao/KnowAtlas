## 1. 这个工具到底在做什么

一句话：**把你散落在各处的知识（浏览器书签、本地文件、思维导图、邮件…）收成一张统一的网，
让你从分类树 / 词云 / 关系图 / 线索 / 时间线五个入口找到它，并且永远能点回原文。**

它不改你的原始数据。原始文件、原始网页都还在原地，工具只在自己的数据库里建一份「共享的
结构化元数据」，所以同一个源可以被多个入口复用，删掉数据库也不会毁掉你的资料。

### 三层结构（理解这个，后面全通）

| 层 | 白话 | 代码位置 |
|---|---|---|
| **适配器** | 「翻译官」：每个源一个文件，只负责把源里的东西翻译成统一格式的「条目」，不抓正文、不分类 | `src/knowatlas/adapters/` |
| **抓取器** | 「取内容的」：按地址类型（http / file / emmx / mail…）去把正文取回来，跨源共享 | `src/knowatlas/fetchers/` |
| **语义处理器** | 「动脑子的」：分类、打标签、抽知识点、查错、判过时——与源无关 | `src/knowatlas/semantic/tasks/` |

两处「地基」：数据库（SQLite，唯一事实来源，`datalayer/` 是唯一能碰它的模块）+ 能力注册表
（`registry/builtins.py`，所有能力只在这里登记）。

## 2. 五分钟跑起来

```powershell
# ① 装依赖（uv 管 Python，本机是 3.13）
uv sync --extra dev

# ② 复制配置（config/ 整个目录不进 git）
copy config\knowatlas.example.toml config\knowatlas.toml

# ③ 建库 + 注册能力（新机器只需一次）
uv run python -m knowatlas kinit

# ④ 启动本地服务
uv run python -m knowatlas serve          # 默认 http://127.0.0.1:8420
```

**没有 `config/knowatlas.toml` 时所有命令都会直接报 `ConfigError` 退出**——这是故意的，不会偷偷用默认值。

### LLM 的 key 怎么给

key 只从环境变量读，不会写进配置、不会进日志。本机已配好三个用户级变量：

```powershell
# 每条需要 LLM 的命令，先在同一窗口导入（用户级变量只对之后新启动的进程生效）
foreach ($n in 'KNOWATLAS_LLM_API_KEY_SF1','KNOWATLAS_LLM_API_KEY','KNOWATLAS_WEB_TOKEN') {
  $v = [Environment]::GetEnvironmentVariable($n,'User'); if ($v) { Set-Item -Path "env:$n" -Value $v }
}
```

**怎么判断 LLM 真的连上了**：`kpoints` 报告里 `split > 0`，或点的 `meta.judge_reason` 里不再出现
「LLM 未启用」。没连上时系统不会报错，而是**安静降级**成「整篇 4023 字当一个点」——这是已知坑（第 11 节）。

## 3. 六个入口（主界面）

打开 `http://127.0.0.1:8420/`，顶部是六个页签，左侧是分类树，右侧是预览面板。

| 页签 | 干什么 | 怎么用 |
|---|---|---|
| **🔍 检索** | 主入口。三个通道一起出结果 | 输入关键词回车；结果分「◆ 知识点」（主通道）和条目卡（点反查 + 直击正文）；`mode=hybrid` 时走向量混合检索 |
| **🕸 关系图** | 分类 → 子分类 → 条目逐层下钻 | 初始只显示一级大类；点节点下钻；点节点上的「🎯 切焦点」看它的一跳关联（每条边都有理由：同分类/同站点/同线索/全文命中）；「🔍 反查」看谁指向当前焦点（知识点会列出溯源条目与分类链） |
| **🧵 线索库** | 把跨条目的内容串成一条线（如「做某事的完整步骤」） | 新建线索 → 拉条目进来 → 用 AI 生成摘要/建议后续 |
| **☁️ 词云** | 一眼看库里什么词最多 | 点分类聚焦到子树；点词=在当前范围内过滤条目 |
| **🕒 时间线** | 按时间看最近收进来的东西 | 按天/月分组浏览 |
| **🛠 管理** | 所有「维护动作」都在这 | 8 个二级页签，见第 5 节 |

### 检索结果的读法

- **知识点（◆）**：从文档里提炼出来的一句完整知识，带「来源」按钮可看原文出处；这是主要看的东西。
- **条目卡**：一篇文档/一个网页/一本书的一章。点标题右侧的 📄 看正文预览，🔗 跳原网页。
- 右上角 `多选` 打勾后，可以批量「移到分类 / 转正 / 舍弃 / 合并 / AI 起名」。

### 预览面板

点任何条目，右侧出预览：正文（纯文本）、分类、标签、**知识点列表**（每条可点「解释」让 LLM 讲清
上下文，也可勾选去做「知识梳理」合成）、来源链接、时效/勘误标记。

**「打开原文」怎么开（2026-10-26 修）**：文件夹源的条目存的是 `file://<配置根相对路径>`
（如 `file://AI-Agents-in-Depth-zh-CN .pdf`），这个写法浏览器自己开不了——所以在页面上点标题、
点预览面板的「打开原文」、点关系图里的条目/反查到的溯源条目，都改走**站内代理**
`/api/entries/<条目ID>/file`：服务端按 `[sources.folders].roots` 把相对路径解析成绝对路径，
PDF 直接由浏览器阅读器打开（可翻页），md/txt 当正文显示，HTML/Office 一律下载不内联。
脑图（`emmx://`）仍不开外链，改看预览面板里的「大纲树」。

## 4. 条目的一生（状态机）

这条必须懂，否则会困惑「为什么我收的东西搜不到」。

| 状态 | 含义 | 怎么进来 / 出去 |
|---|---|---|
| `pending` 待审 | 已入库，但**不进消费面**（不参与检索、分类、抽点） | 源配置 `new_entries="pending"` 时的新条目；管理页「🆕 待审」批量 **✅转正** 或 **🗑舍弃** |
| `active` 在库 | 正常可搜可用 | 转正后 |
| `rejected` 已舍弃 | 你明确不要了；**再同步也不会自动回来** | 舍弃 → 30 天冷却期 → 期满自动物理删除（可 `restore` 反悔） |
| `archived` 源里消失 | 原始来源没了（文件被删、网页 404 归档） | 同步时自动；源恢复可复活 |

> 注意：管理页的「📥 暂存区」**不是一种状态**，它列的是「还没挂到任何分类」的条目（`active` 但无分类）。

除了状态，条目身上还挂几种**标记**（互不干扰）：

- `link_status=dead`：链接体检发现 404/410 → 管理页「☠️ 失效链接」
- `value_flag=not_knowledge`：价值体检判定「不是知识」（资源直链、站点首页、列表子页）→「🔬 待清理」
- `freshness_flag=suspect/stale`：时效体检判定可能过时 →「⏳ 老化候选」
- `errata`：勘误标记（L1 规则扫描发现确定性错误）→「🩹 勘误裁决」

## 5. 管理页的八个页签（日常主要在这里干活）

| 页签 | 里面是什么 | 典型操作 |
|---|---|---|
| 📥 **暂存区** | 已入库但**还没挂分类**的条目（不是一种状态） | 拖到左树分类上，或点条目「⇄改分类」归类 |
| 🆕 **待审** | 已入库但没进消费面的（当前 161 条）；支持按文件夹分组、按关键词就地筛选、全选可见 | 全选 → **✅转正**（进检索）/ **🗑舍弃** / **⇒合并** / **移到…** |
| 🔬 **待清理** | 被判「不是知识」的条目 | 看一眼→ 确认丢弃 / 申诉解除标记 |
| ☠️ **失效链接** | 体检发现 404/410 的 | 打开原页确认 / 舍弃 / 解除标记 |
| ⏳ **老化候选** | 时效规则标「可能过时」的 | 人工判定：确认过时 / 解除标记 |
| 🩹 **勘误裁决** | 勘误扫描标出的确定性问题 | 逐条看理由与依据 → 确认 / 驳回 |
| 🗑️ **已舍弃** | 你舍弃的（冷却期内） | **restore 反悔** |
| 🛠 **数据管理** | 库的整体操作 | 快照备份 / 导出 / 统计 / 链接体检 / 重分类 / 向量重建 |

### 批量操作（左下浮动条）

先勾「多选」（或列表头部的复选框）→ 条目左侧出现勾选框 → 底部浮出工具条：

- **移到…**：把选中的条目搬进某个分类（输入完整路径，有下拉提示）
- **✅ 转正**：待审 → 在库
- **🗑 舍弃**：→ 已舍弃（30 天冷却，可反悔）
- **⇒合并**：勾 ≥2 条，**第一条为主条目**，其余的链接/知识点/分类全部归它，其余的置已舍弃
- **✨ AI 起名**：按正文生成知识化的短名字（默认提示词可改；已有名字的跳过）

> 半年前的老坑：页面被浏览器缓存导致「勾了没反应」。已修（HTML 一律 `Cache-Control: no-store`），
> 页脚有构建时间，变红说明你浏览器里还是旧页面，`Ctrl+F5`。

### 分类树上的操作

右键/悬浮分类节点会出现操作：新建子分类、改名、移动、合并进另一分类（其条目与子树并入、
本分类删除）、删除。**分类可以手动校正，人工改过的分类不会被自动重分类覆盖。**

## 6. 命令行：13 个命令

所有命令都是 `uv run python -m knowatlas <命令>`。常用参数都列了，长尾参数用 `--help` 看。

### 6.1 `kinit` — 建库

```bash
uv run python -m knowatlas kinit
```

建表 + 注册内置能力 + 记一条 run。新机器/清库后跑一次。

### 6.2 `kadd` — 贴链接收录（手动入口）

```bash
uv run python -m knowatlas kadd https://example.com/article
```

抓正文 → 归类 → 入树。一次可贴多个 URL。
**网页版更省事**：管理页左侧「📮 收藏」小书签拖到浏览器书签栏，任意网页点一下即收录（走同一条链路）。

### 6.3 `ksync` — 批量同步与各种「体检/维护」（最常用的一个）

```bash
uv run python -m knowatlas ksync                    # 增量同步所有已配置的源 + 分类
uv run python -m knowatlas ksync --full             # 全量遍历型源全量拉取
uv run python -m knowatlas ksync --source bookmarks # 只同步某个源
uv run python -m knowatlas ksync --dry-run          # 只探测源可达性，不写库
uv run python -m knowatlas ksync --fetch-limit 20   # 显式开启抓正文（默认不抓，最多 20 条）
uv run python -m knowatlas ksync --reclassify       # 对全库重跑分类（跳过人工校正过的）
uv run python -m knowatlas ksync --value-scan       # 价值体检：标出不是知识的内容（零费用）
uv run python -m knowatlas ksync --dedupe-scan      # 跨源去重：同一篇合并为一条（可逆）
uv run python -m knowatlas ksync --freshness-scan   # 时效体检：标出可能过时的（只标不删）
uv run python -m knowatlas ksync --errata-scan      # 勘误 L1：确定性错误扫描（零费用）
uv run python -m knowatlas ksync --purge-source emmx --dry-run   # 全删重灌预演
uv run python -m knowatlas ksync --expand <条目ID> --expand-limit 20   # 书签扩散抓取
uv run python -m knowatlas ksync --embed            # 构建/增量更新向量索引
uv run python -m knowatlas ksync --cluster-report   # 暂存区聚类 + 起名候选（人确认后才建类）
```

**几处必须知道的行为**：

- 默认 `on_sync=false`：同步只入库不抓正文，要抓得显式给 `--fetch-limit N`。
- `--dry-run` 可以配体检类参数，只出报告不动库——**先干跑再真跑**是好习惯。
- 每次 sync 会自动做两件事：超时快照（默认 24h 一份）、清扫冷却期满的已舍弃条目。
- **扩散抓取**（`--expand`）：对某个书签，抓「同目录下的同主题系列页」（同一 host + 同一父目录），
  每轮最多 20 条；对 GitHub 仓库/树目录会专门收集仓库内的文件，最多下钻 2 层。**只对文档站、
  系列博客、代码仓库有效**；对知乎/掘金/公众号这类「一个 ID 一篇文章」的站点没意义。

### 6.4 `serve` — 起服务

```bash
uv run python -m knowatlas serve --port 8420
```

默认 `127.0.0.1:8420`。**换端口要用 `--port`**（会同步回写配置里的白名单，否则访问被拒）。

### 6.5 `kpoints` — 抽知识点

```bash
uv run python -m knowatlas kpoints --limit 20        # 抽 20 条
uv run python -m knowatlas kpoints --dry-run         # 只判定与报告，不写库（LLM 费用照付）
uv run python -m knowatlas kpoints --purge-points    # 先清空点层再抽（口径变更后重来）
uv run python -m knowatlas kpoints --retry-blocked   # 把被自洽性闸门拦下的条目重抽
uv run python -m knowatlas kpoints --triage --from-json temp/errata_full_triage.json  # 点分诊（导入既有结果，零 LLM 费）
uv run python -m knowatlas kpoints --triage --limit 20   # 只给新入库的点做分诊（走 LLM，30/批）
```

规则：文学创作类走 LLM 切分（split，一本书多个点），其余「整篇即一点」（integral）；相同内容
按 hash 去重，一个点可以挂多个来源。抽完的点可被检索到（◆ 知识点通道）。

**点分诊（`--triage`，2026-10-25 起）**：给每个点贴 `meta.kind`——
`hard`（可判对错的硬事实）/ `opinion`（观点方法论）/ `unjudgeable`（内部实现·预测·无法核查）/
`dupe`（重复点，按 `meta.dupe_of` 自动标）。现有 4,552 点分布：hard 1,579 / opinion 2,016 /
unjudgeable 914 / dupe 43。这是**领域闸门**：后续勘误（`kerrata --points`）与老化
（`kaging --lifecycle`）只吃 `hard`，其余永不判对错、不判过时（这两个入口尚在 P1/P2 开发中，
现有 `kerrata`/`kaging` 仍是条目级/点级旧口径，尚未接闸）。
重跑幂等（已有 kind 的不重判）；不写 `--from-json` 时新点走 LLM，LLM 不可用则整批跳过、不改库。

### 6.6 `kpeimport` — 导入外部长文抽取产物

```bash
uv run python -m knowatlas kpeimport <kpe的输出目录> --entry <条目ID> [--replace] [--dry-run]
uv run python -m knowatlas kpeimport <out> --match "*Hello-Agents*"
```

长书/长 PDF 用独立工具 `kpe`（分块 → 抽取 → 复核，产物 `manifest.json` + `points.jsonl`），
再用这条命令入库。点的 meta 会带上 `extractor="kpe"`、书名、章节路径、原文引用。

### 6.7 `kaging` — 老化（时效）

```bash
uv run python -m knowatlas kaging --limit 10     # L2：LLM 复核「疑似过时」的条目
uv run python -m knowatlas kaging --points       # 点级：只老化确实过时的点，条目过时不连坐
uv run python -m knowatlas kaging --sweep        # L3：物理删除冷却期满（30 天）的已舍弃条目
```

三级流水线：L1 规则扫描（`ksync --freshness-scan`，看废弃关键词/正文日期/新旧并存）→
L2 LLM 逐条复核（升级 `stale` / 否决 / 下沉人工）→ L3 删除出口（**只删你亲手舍弃且过冷却期的**）。

### 6.8 `kerrata` — 勘误

```bash
uv run python -m knowatlas kerrata --scan        # L1：确定性错误（代码块语法、已移除 API），零费用
uv run python -m knowatlas kerrata --limit 10    # L2：LLM 带依据核查（默认 10 条试跑口径）
uv run python -m knowatlas kerrata --points --from-json temp/errata_full_verify.json  # 点级核查（回放既有结果，零 LLM 费）
uv run python -m knowatlas kerrata --points --limit 20   # 只核新入库的 hard 点（走 LLM）
```

判错必须附可核查依据，给不出依据会自动降级为「疑似」，不进入裁决队列。**只标不删**，
原文永不改动。

**点级核查（`--points`，2026-10-25 起）**：只核 `kind=hard` 的点（`opinion`/`unjudgeable`/`dupe`
一律不判），结论落点 meta 的 `fact_check`（`wrong`/`suspect`/`ok` + 理由 + 依据 + 原因码
`fact_error`/`overclaim`）。`wrong` 进点级队列 `GET /api/errata/points`（带理由、依据、溯源条目），
`suspect` 不进队列。现有 1,579 个 hard 点：wrong 37 / suspect 348 / ok 1,194。重跑幂等。
**注意**：管理页「🩹 勘误裁决」页签目前仍只列条目级结果，点级队列暂时只能通过 API 看（P1b 会接页签）。

### 6.9 `kcheck` — 链接体检

```bash
uv run python -m knowatlas kcheck --limit 100 --qps 4
```

逐条访问链接，404/410 标 `dead`，进「☠️ 失效链接」。

### 6.10 `kexport` — 导出

```bash
uv run python -m knowatlas kexport --format json --out exports/knowledge.json
uv run python -m knowatlas kexport --format obsidian --out exports/vault
uv run python -m knowatlas kexport --format opml --out exports/feeds.opml
```

### 6.11 `kbackup` — 快照与恢复

```bash
uv run python -m knowatlas kbackup --snap                  # 立即快照并轮换（默认保留 10 份）
uv run python -m knowatlas kbackup --restore <快照文件>     # 恢复（恢复前自动再拍一份安全网）
uv run python -m knowatlas kbackup --verify <快照文件>      # 恢复演练：完整性 + 条目数核对
```

同步时也会自动快照（默认最短间隔 24 小时）。

### 6.12 `ktest` — 回归集与契约金丝雀

```bash
uv run python -m knowatlas ktest canary    # 契约金丝雀：枚举/scheme/端点有没有被悄悄改坏
uv run python -m knowatlas ktest regress   # 回归集：历史分类决策有没有被改坏
```

### 6.13 `<其它>` — 测试与本地探针

```bash
uv run python -m pytest -q                     # 全量测试：只打点，退出码 0 即全绿
uv run python -m pytest -o addopts="" -q       # 想看汇总行用这个（当前 580 passed / 1 skipped）
```

> 小坑：`pyproject.toml` 里 `addopts = "-q"`，你再带一个 `-q` 就成了 `-qq`，pytest 会**连汇总行都不打**，
> 只剩一串点。所以「看不到 passed 数字」不等于失败，看退出码。

## 9. 数据安全

| 约束 | 具体表现 |
|---|---|
| 只监听本机 | 默认 `127.0.0.1`，有 Host 白名单，别的主机名访问直接 `FORBIDDEN_HOST` |
| 写操作三件套 | `X-KnowAtlas-Token` 头 + `Content-Type: application/json` + Host/Origin 命中白名单，缺一不可 |
| 令牌 | 环境变量 `KNOWATLAS_WEB_TOKEN`；**没设时启动会随机生成一次性令牌并打印在日志里，重启即失效** |
| 凭证不入库 | 配置里只写 `*_env` 变量名，密钥只在环境变量里 |
| 只读 MCP | `/api/mcp/search`、`/api/mcp/entry/{id}`、`/api/mcp/tree` 三个只读端点，供外部 AI 工具查库 |
| 原始数据不动 | 只读源文件；删除只删数据库里的条目与正文副本 |

**误删了怎么办**：管理页「🗑️ 已舍弃」里点 restore（30 天内）；过了 30 天就没了——
但数据库快照还在（`data/` 下的 `knowledge-*.db`），可用 `kbackup --restore` 回滚。

## 11. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 所有命令报 `ConfigError` | 没有 `config/knowatlas.toml` | 复制 `knowatlas.example.toml` |
| 中文输出乱码 | Windows 控制台 GBK | `chcp 65001` + `$env:PYTHONIOENCODING='utf-8'` |
| 抓不到正文但没报错 | LLM key 没生效（用户级变量只对之后启动的进程生效） | 按第 2 节重新导入；看 `kpoints` 报告 `split>0` |
| 页面 403 `FORBIDDEN_HOST` | 换了端口没回写白名单 | 用 `serve --port N`（会回写），别手改 |
| 页面操作报 401/403 | 缺 token 头或 content-type | 正常页面会自动带；脚本调用要带齐三件套 |
| 换了端口后 API 全 502 | 脚本走了系统代理（`HTTP_PROXY`） | 本地请求加 `trust_env=False` |
| 勾了条目浮动条不出现 | 浏览器还是旧页面 | 看页脚构建时间，`Ctrl+F5` |
| 一批条目搜不到 | 它们在 `pending` 里（不进消费面） | 管理 → 待审 → 转正 |
| 同一个网页入库两次 | 不同源给了不同地址 | `ksync --dedupe-scan` 合并（可逆） |
