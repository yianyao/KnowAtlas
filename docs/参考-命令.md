## `kaging`

老化三级：L2 LLM 复核 suspect（升级 stale/否决/下沉人裁）；--sweep 执行冷却期满删除出口（方案 §7.5）

用法：`knowatlas kaging [-h] [--limit LIMIT] [--dry-run] [--sweep] [--points]
                        [--lifecycle]`

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--limit` | `LIMIT` | — | 本次最多复核条数（条目/点级默认 10=试跑口径，全量须用户裁决；--lifecycle 默认不限=全库） |
| `--dry-run` | `DRY_RUN` | false | 只判定与报告，不写库（LLM 费用照常发生；--sweep 时只出删除报告） |
| `--sweep` | `SWEEP` | false | 执行删除出口清扫：冷却期满（30 天）的 rejected 条目物理删除+ content_store 引用计数回收（审计留痕）；默认每轮 ksync 自动执行 |
| `--points` | `POINTS` | false | 点级老化 L2（批次 93，裁决 #14）：对溯源条目被标 suspect/stale 的点逐点复核——条目过时不连坐点，确证过时的点退出消费面（溯源条目保留，永不物理删除） |
| `--lifecycle` | `LIFECYCLE` | false | 点级老化两型（P2）：版本型按官方 EOL 表确定性判（零 LLM）+ 退场型按技术栈 LLM 判（必附官方依据否则 keep）；只吃 kind=hard，stale 退出消费面，只标不删；幂等（meta.lifecycle.at 游标） |

## `kcheck`

库体检：链接可达性（404/410 标记 dead） / 正文库孤儿回收（--gc-content）

用法：`knowatlas kcheck [-h] [--limit LIMIT] [--qps QPS] [--gc-content]
                        [--gc-days GC_DAYS] [--dry-run]`

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--limit` | `LIMIT` | 100 | 本次最多检测条数（默认 100） |
| `--qps` | `QPS` | 4.0 | 检测速率（默认 4 条/秒） |
| `--gc-content` | `GC_CONTENT` | false | 回收无条目引用的正文块（content_store 孤儿；不联网、不动条目/点/向量，正文可重抓） |
| `--gc-days` | `GC_DAYS` | 1.0 | （--gc-content）只回收抓取时间早于 N 天的孤儿正文（默认 1；阈值防同步进行中的竞态） |
| `--dry-run` | `DRY_RUN` | false | （--gc-content）只统计不删除 |

## `kerrata`

勘误三级：--scan 跑 L1 确定性错误扫描（零费用）；--points 跑点级事实核查（P1，只吃 kind=hard）；默认跑 L2 带依据核查（方案 §7.6）

用法：`knowatlas kerrata [-h] [--limit LIMIT] [--dry-run] [--scan] [--points]
                         [--from-json PATH] [--backfill-codes]`

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--limit` | `LIMIT` | — | 本次最多核查条数（条目 L2 默认 10=试跑口径；--points 默认不限） |
| `--dry-run` | `DRY_RUN` | false | 只判定与报告，不写库（LLM 费用照常发生；--scan 时只出报告） |
| `--scan` | `SCAN` | false | 跑 L1 确定性错误扫描（完整 Python 代码块语法验证 + 已移除 API 对照表，零费用；同 ksync --errata-scan） |
| `--points` | `POINTS` | false | 点级事实核查（P1）：hard 点判 wrong/suspect/ok，结论落 point.meta.fact_check；wrong 进 /api/errata/points 队列，suspect 只进筛选视图；只标不删、幂等 |
| `--from-json` | `PATH` | — | --points 时回放既有核查产物（{point_id:{verdict,reason,evidence}}，零 LLM 费）；推荐的默认种子：temp/errata_full_verify.json |
| `--backfill-codes` | `BACKFILL_CODES` | false | --points 时只回填原因码（P1b）：给已判 wrong 但 reason_code 为空的点补 fact_error/overclaim，不重判 verdict/reason/evidence；幂等，与 --from-json 互斥 |

## `kpoints`

知识点抽取：规则判定（文学创作=split 切点，其余 integral 整条即点，用户口径 2026-10-22）→ hash 去重一点多溯源

用法：`knowatlas kpoints [-h] [--limit LIMIT] [--dry-run] [--entry ENTRY_ID]
                         [--purge-points] [--retry-blocked] [--triage]
                         [--from-json PATH]`

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--limit` | `LIMIT` | — | 本次最多处理条数（抽取默认 10；--triage 默认不限；--limit 0 仅 purge） |
| `--dry-run` | `DRY_RUN` | false | 只判定与报告，不写库（split 切点的 LLM 费用照常发生） |
| `--entry` | `ENTRY_ID` | — | 定向补抽：只抽指定条目（可重复）。注意沿用批次 70 语义——跳过游标、会重新调用 LLM（点 hash 相同只归并溯源，不重复建点）；想先看费用用 --dry-run |
| `--purge-points` | `PURGE_POINTS` | false | 先清空点层（points/point_sources）再抽取——形态判定口径变更后的推倒重来；条目与原文零影响 |
| `--retry-blocked` | `RETRY_BLOCKED` | false | 把被自洽性闸门拦下的条目（meta.points_gate）清标记后重抽——口径/prompt 调整后的重试入口 |
| `--triage` | `TRIAGE` | false | 点分诊（P0）：给点打 kind=hard|opinion|unjudgeable|dupe，落 meta；后续勘误/老化只吃 hard（领域闸门）。幂等，已有 kind 的跳过 |
| `--from-json` | `PATH` | — | --triage 时导入既有分诊产物（{point_id:{kind,why}}，零 LLM 费）；推荐的默认种子：temp/errata_full_triage.json |

## `ksync`

同步编排：书签等批量源 → 幂等入库 → 分类

用法：`knowatlas ksync [-h] [--full] [--incremental] [--source SOURCE]
                       [--dry-run] [--limit LIMIT] [--fetch-limit FETCH_LIMIT]
                       [--entry ENTRY_ID] [--reclassify] [--value-scan]
                       [--dedupe-scan] [--freshness-scan] [--errata-scan]
                       [--purge-source SOURCE] [--purge-reason REASON]
                       [--expand ENTRY_ID] [--expand-limit EXPAND_LIMIT]
                       [--embed] [--embed-force] [--cluster-report]`

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--full` | `FULL` | false | 全量遍历型源全量拉取 |
| `--incremental` | `INCREMENTAL` | false | 游标型源增量 |
| `--source` | `SOURCE` | — | 只同步指定源 |
| `--dry-run` | `DRY_RUN` | false | 只探测源可达性，不写库 |
| `--limit` | `LIMIT` | — |  |
| `--fetch-limit` | `FETCH_LIMIT` | — | 显式开启本次抓取，最多 N 条（默认 on_sync=false 不抓；候选只取 active，刚转正的排最前） |
| `--entry` | `ENTRY_ID` | — | 定向补抓：只处理指定条目（可重复）——不看状态、默认抓正文，且不归档（定向≠全量遍历，--full 在此模式下不生效） |
| `--reclassify` | `RECLASSIFY` | false | 对库中全部条目重跑分类（跳过人工校正过的；[llm] 启用且 key 已设时走 LLM 语义分类） |
| `--value-scan` | `VALUE_SCAN` | false | 价值体检：纯规则标记非知识内容（资源直链/站点首页/列表子页），零费用、不动分类树；配合 --dry-run 只出报告 |
| `--dedupe-scan` | `DEDUPE_SCAN` | false | 跨源去重存量扫描：canonical/正文 hash 完全一致的条目合并为一条（主条目保留全部 locator 可跳转，副条目隐藏、可逆）；配合 --dry-run 只出报告 |
| `--freshness-scan` | `FRESHNESS_SCAN` | false | 时效体检：纯规则标记过期/疑似过旧的知识（废弃关键词/正文日期过旧/同主题新旧并存），只标不删、可否决；配合 --dry-run 只出报告 |
| `--errata-scan` | `ERRATA_SCAN` | false | 勘误 L1 体检：纯规则确定性错误扫描（完整 Python 代码块语法验证/已移除 API 对照表），只标不删、可否决；配合 --dry-run 只出报告 |
| `--purge-source` | `SOURCE` | — | 全删重灌第一步：物理删除指定源全部条目（含 archived/rejected，FK 级联+ content_store 引用计数回收 + task_log 留痕）后接着同步该源；先快照后删除（快照失败自动中止）；配合 --dry-run 只探测不删除 |
| `--purge-reason` | `REASON` | reingest | purge 留痕原因标记（默认 reingest；emmx 重灌用 emmx_rebuild） |
| `--expand` | `ENTRY_ID` | — | 书签扩散抓取（显式触发）：对指定书签/http 条目抓取其同目录系列页（同一目录页同一主题） |
| `--expand-limit` | `EXPAND_LIMIT` | 20 | 扩散每轮最多新建条数（默认 20） |
| `--embed` | `EMBED` | false | 构建/增量更新条目向量索引（M4，需 [embedding] + optional 依赖） |
| `--embed-force` | `EMBED_FORCE` | false | 重算全部向量（换模型后用） |
| `--cluster-report` | `CLUSTER_REPORT` | false | 暂存区条目聚类 + LLM 命名候选报告（不建类，人工确认后生效） |
