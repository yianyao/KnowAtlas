## 3. 契约一定稿：统一数据层

### 3.1 条目字段完整定义

| 字段 | 类型 | 必填 | 约束（代码层强制） |
|---|---|---|---|
| id | TEXT(16) | 是 | `^[0-9a-f]{16}$`；由 §3.3 规则生成，禁止手工指定 |
| source_type | TEXT | 是 | 枚举见 §3.2；写入前白名单校验 |
| title | TEXT | 是 | 允许空串；UI 回退显示 locator 末段 |
| locator | TEXT | 是 | 符合 §5 scheme 规范；`file://` 内禁止绝对机器路径；**主 locator**（同一知识的其余 locator 由 entry_locators 表承载，见 §3.4） |
| native_path | TEXT \| None | 否 | 源自带路径，`/` 分隔；先验信号来源 |
| inline_content | TEXT \| None | 否 | ≤ 4096 字符的轻量正文；超出部分入 content_store，本字段留摘要 |
| content_hash | TEXT(40) | 否 | sha1 十六进制；规范化后计算（§3.3） |
| meta | TEXT(JSON) | 是 | 合法 JSON 对象，默认 `{}`；键名小写 snake_case |
| created_at | TEXT \| None | 否 | ISO 8601（带时区或朴素本地时间均可）；解析失败置 NULL，**不臆造** |
| exported_at | TEXT | 是 | ISO 8601，导入时刻 |
| status | TEXT | 是 | active / archived / deleted，默认 active |

class Entry:

    title: str

    native_path: str | None
    inline_content: str | None
    content_hash: str | None
    meta: dict[str, Any]
    created_at: str | None
    exported_at: str

### 3.2 source_type 枚举与源内唯一键（ID 生成依据）

| source_type | 含义 | 源内唯一键（source_key） |
|---|---|---|
| bookmark | 浏览器收藏夹 | `浏览器名 + 书签节点 id`（无 id 时用 `收藏夹路径 + 标题` 兜底） |
| folder | 办公文件夹文件 | 规范化路径（相对配置根目录） |
| emmx | 万兴脑图节点 | `脑图文件相对路径 + 节点 UUID` |
| mail | 邮件 | `maildir 相对路径 + Message-ID` |
| ima | IMA 笔记 | note_id |
| txdoc | 腾讯文档 | 官方文件/文件夹 ID |
| db | 数据文件对象 | `文件相对路径或连接串名 + 表名` |
| session | AI 会话 | session_id |
| wxfav | 微信收藏（种子条目） | 收藏项本地标识（解密产物 id 或手动清单行号） |
| manual | 手动粘贴链接 | canonical URL（§3.3） |
| wxchat | 微信聊天记录 | `导出文件相对路径 + 会话 id + 消息 id` |
| wxarticle | 公众号扒取文章（关联条目） | `biz + 文章 aid（或 URL）` |
| bili | B站收藏夹视频 | `bvid/avid`（同一视频进多个收藏夹只产一条；全部收藏夹 id 进 meta.fav_folder_ids，native_path 取首个收藏夹名） |

### 3.3 ID / canonical URL / 内容 hash 规则（ids.py 定稿）

```
entry_id  = sha1(f"{source_type}\x1f{source_key}".encode()).hexdigest()[:16]
```

- `\x1f` 作分隔符防碰撞（如路径里恰好含 `|`）。
- 重复导入同一源内容 → id 不变 → upsert 语义（§4.3）。

canonical URL 规范化（manual/bookmark 判重与 ID 依据）：

1. scheme 与 host 转小写；host 去默认端口（http:80 / https:443）。
2. 去 `www.` 前缀（仅 host 以 `www.` 开头且去后仍可访问时；无法探测时保守保留——**默认保留**，避免误合并）。
3. 去 fragment（`#` 及之后）。
4. query 参数：去跟踪参数（utm_*、spm、from、share_* 等，清单在 `ids.py::TRACKING_PARAMS`），其余按 key 排序后重建。
5. path 去尾斜杠（根路径除外）；path 大小写保留（服务器语义未知，不动）。

内容 hash（判重与缓存依据）：

1. 统一 LF；去每行首尾空白；压缩连续空行为一个空行；去首尾空行。
2. `content_hash = sha1(规范化文本.encode()).hexdigest()`

### 3.4 完整 DDL（schema.py 定稿，user_version = 1）

```sql
PRAGMA user_version = 1;

CREATE TABLE entries (
    id                TEXT PRIMARY KEY,
    source_type       TEXT NOT NULL,
    title             TEXT NOT NULL,
    locator           TEXT NOT NULL,          -- 主 locator；其余见 entry_locators
    locator_canonical TEXT,                   -- https 主 locator 规范化形式；kadd 判重走此索引
    native_path       TEXT,
    inline_content    TEXT,
    content_hash      TEXT,
    meta              TEXT NOT NULL DEFAULT '{}',
    created_at        TEXT,
    exported_at       TEXT NOT NULL,
    status            TEXT NOT NULL DEFAULT 'active'
);
CREATE INDEX idx_entries_source   ON entries(source_type);
CREATE INDEX idx_entries_status   ON entries(status);
CREATE INDEX idx_entries_exported ON entries(exported_at);
CREATE INDEX idx_entries_hash     ON entries(content_hash);
CREATE INDEX idx_entries_loccanon ON entries(locator_canonical);

CREATE TABLE entry_locators (            -- 一条知识的多个定位（跨源合并的落点）
    entry_id   TEXT NOT NULL REFERENCES entries(id) ON DELETE CASCADE,
    locator    TEXT NOT NULL,
    scheme     TEXT NOT NULL,
    is_primary INTEGER NOT NULL DEFAULT 0,
    UNIQUE (entry_id, locator)
);
CREATE INDEX idx_entryloc_locator ON entry_locators(locator);
CREATE INDEX idx_entryloc_scheme  ON entry_locators(scheme);

CREATE TABLE categories (
    id         TEXT PRIMARY KEY,
    name       TEXT NOT NULL,
    note       TEXT,
    origin     TEXT NOT NULL,            -- prior / rule / embedding / llm / manual
    created_at TEXT NOT NULL
);
-- path 不落库：由 category_parents + 递归 CTE 派生（多父分类有多条路径）。
-- 存 path 会在每次 move 时级联重写整棵子树，是持续的债；见 §3.5 get_category_by_path。

CREATE TABLE category_parents (           -- DAG：一个分类可有多个父分类
    category_id TEXT NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
    parent_id   TEXT NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
    PRIMARY KEY (category_id, parent_id)
);
CREATE INDEX idx_catparents_parent ON category_parents(parent_id);

CREATE TABLE entry_categories (           -- 条目-分类多对多
    entry_id    TEXT NOT NULL REFERENCES entries(id) ON DELETE CASCADE,
    category_id TEXT NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
    confidence  REAL NOT NULL DEFAULT 1.0,
    origin      TEXT NOT NULL,
    task_run_id TEXT,
    PRIMARY KEY (entry_id, category_id)
);
CREATE INDEX idx_entrycats_category ON entry_categories(category_id);
CREATE INDEX idx_entrycats_origin   ON entry_categories(origin);

CREATE TABLE content_store (              -- 大正文缓存，同一内容只存一份
    content_hash TEXT PRIMARY KEY,
    text         TEXT NOT NULL,
    fetched_at   TEXT NOT NULL,
    fetcher      TEXT NOT NULL
);
CREATE INDEX idx_content_fetched ON content_store(fetched_at);

CREATE TABLE task_log (                   -- 审计与增量处理基础
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    at        TEXT NOT NULL,
    task_name TEXT NOT NULL,
    action    TEXT NOT NULL,              -- classify / retag / merge / move / archive / import
    target    TEXT NOT NULL,
    detail    TEXT NOT NULL DEFAULT '{}'
);
CREATE INDEX idx_tasklog_at     ON task_log(at);
CREATE INDEX idx_tasklog_target ON task_log(target);

CREATE TABLE runs (                       -- 每次同步/任务运行的记录（可回溯、可重放）
    id          TEXT PRIMARY KEY,
    kind        TEXT NOT NULL,            -- sync_full / sync_incremental / kadd / task:<name>
    started_at  TEXT NOT NULL,
    finished_at TEXT,
    stats       TEXT NOT NULL DEFAULT '{}'
);

CREATE VIRTUAL TABLE entries_fts USING fts5(
    title, native_path, inline_content,
    content = 'entries',
    tokenize = 'trigram'
);

CREATE VIRTUAL TABLE content_fts USING fts5(   -- 大正文索引（H2：正文原先无索引覆盖）
    content_hash UNINDEXED,
    text,
    tokenize = 'trigram'
);

-- 外部内容表必须配触发器保持同步
CREATE TRIGGER entries_ai AFTER INSERT ON entries BEGIN
    INSERT INTO entries_fts(rowid, title, native_path, inline_content)
    VALUES (new.rowid, new.title, new.native_path, new.inline_content);
END;
CREATE TRIGGER entries_ad AFTER DELETE ON entries BEGIN
    INSERT INTO entries_fts(entries_fts, rowid, title, native_path, inline_content)
    VALUES ('delete', old.rowid, old.title, old.native_path, old.inline_content);
END;
CREATE TRIGGER entries_au AFTER UPDATE ON entries BEGIN
    INSERT INTO entries_fts(entries_fts, rowid, title, native_path, inline_content)
    VALUES ('delete', old.rowid, old.title, old.native_path, old.inline_content);
    INSERT INTO entries_fts(rowid, title, native_path, inline_content)
    VALUES (new.rowid, new.title, new.native_path, new.inline_content);
END;
```

连接纪律：`sqlite3.connect(db_path)` 后必设 `PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON; PRAGMA busy_timeout=5000;`。

备份纪律：WAL 模式下**禁止**直接拷贝主库文件做快照（可能拿到不一致状态、且丢 WAL 内已提交事务）；快照必须用 `VACUUM INTO '<snapshot>'` 或 `sqlite3.Connection.backup()`；恢复时先停服务 → 覆盖主库 → 删除同目录 `-wal` / `-shm` → 再启动（旧 WAL 回放会污染新库）。

配套数据结构（models.py）：

```python
@dataclass(frozen=True)
class UpsertResult:
    created: int; updated: int; unchanged: int
    ids: list[str]

@dataclass(frozen=True)
class FetchResult:
    text: str
    content_hash: str      # ids.content_hash() 计算后由 pipeline 填入
    fetcher: str           # 后端名，如 "http_simple" / "http_deepseek" / "file_reader"

```

防腐化红线（代码评审检查项）：`grep -rn "sqlite3.connect" src/` 只允许命中 `datalayer/db.py`；`grep -rn "INSERT INTO\|UPDATE .* SET\|DELETE FROM" src/` 同理。

### 3.6 同步策略定稿（H3 返工）

源分两类，`ksync` 按类型走不同差分逻辑：

| 类型 | 源 | 策略 |
|---|---|---|
| 全量遍历型 | bookmark / folder / emmx / bili / session / db / wx 文件产物 | 每次全量拉取（个人量级成本极低）+ 幂等 upsert 差分 + **删除检测**：本次未见且库中 status=active 的条目 → 置 archived，写 task_log（action=archive，detail 记 `missing_in_source`），**不物理删除** |
| 游标型 | mail / ima / txdoc | 各自游标增量（邮件 UID、IMA 更新时间、腾讯文档变更时间） |

- 删除检测只对全量遍历型源生效；游标型源的删除由源侧不保证，不做检测。
- archived 条目在 UI 归档区可见，可手动恢复（set_status）；不进分类树默认视图。
- 作废表述：SOP 原"只拉取 exported_at 之后的新增/变更"——exported_at 是导入时刻，源侧没有这条时间轴。

安全约束（H5 返工定稿）：仅绑 127.0.0.1 **不够**——挡不住 CSRF 与 DNS rebinding，浏览器里任意网页都能往本地库灌条目并触发 DeepSeek Fetch 计费。必须叠加五条：

1. **Host 校验**：仅接受 `127.0.0.1:<port>` / `localhost:<port>` 的 Host，其余 403；
2. **Origin 校验**：带 Origin 头的请求（浏览器跨站必带）须为 `http://127.0.0.1:<port>` / `http://localhost:<port>`，其余 403；
3. **写操作 token**：`POST /api/entries` 与 `POST /api/corrections` 必须带 `X-KnowAtlas-Token` 头（值取 `[web] token_env` 指向的环境变量）；缺失或错误 403；
4. **content-type 白名单**：写操作仅收 `application/json`，其余 415；
5. **CORS 不放宽**：GET 只读端点不要求 token（本机浏览器直接用）；bookmarklet 的 no-cors POST 把 token 放 query 参数 `?token=`（本地服务场景可接受）。

## 9. 语义流水线与抓取后端细则

### 9.1 classify_coarse 流水线（tasks/classify_coarse.py）

```
输入 batch → L0 价值守卫（value_guard.py：URL 结构规则判「非知识内容」，命中即短路——
            不占 L1/L2/L3、不调 LLM；tags=[not_knowledge, value_reason:<规则>]，
            判定结论与 LLM kind=non 同构，同走 meta.value_flag=not_knowledge 待清理候选）
          → L1 先验映射（priors.py：native_path 前缀表，命中即 confidence=1.0, origin=prior）
          → L2 规则（rules.py：关键词/正则/域名；confidence=0.8, origin=rule）
          → L3 embedding 聚类 + LLM 命名（未命中条目向量化聚类，LLM 为簇命名生成候选路径；
             origin=embedding/llm；置信度按模型输出）
          → 仍无结果 → 不入库分类（进未分类暂存区，绝不硬猜）
```

执行纪律：

- L0 三类规则（2026-10-20 用户定调"结构可判的不花 LLM"）：`resource_file`（path 尾段
  扩展名 ∈ 资源类：压缩包/安装包/镜像/媒体/图片/二进制库；PDF/电子书/Office 不判——
  可解析正文的知识资源）、`portal_homepage`（http(s) path 为空或 "/"）、`index_subdir`
  （http(s) path 以 "/" 结尾且非根）。误判可经 Web UI「是知识，保留」否决
  （`value_flag=ok`，之后 L0 与 LLM 都不再标记）。存量条目打标走
  `ksync --value-scan`（零费用、不动分类树），不走 `--reclassify`。
- 每级可单独关闭（`llm.enabled=false` 时 L3 的 LLM 半级跳过，仅输出 embedding 聚类候选）。
- 每批处理写 `runs`（kind=`task:classify_coarse`）与 `task_log`（action=classify，detail 含输入 id 清单与各级命中数）。
- LLM prompt 模板版本号进 CapabilitySpec.version；换模板必须升版并在回归集上比对。

- inline_content 已内联的条目（邮件正文、脑图节点）→ 不过 fetcher，直传。

### 9.4 主题工作区与放射导航（Thread + Radial，2026-10-20 增补，契约草案）

> 来源：用户痛点「知道要什么，但相关知识散落多个源多个条目，串联困难」+「知道大概方向，
> 想顺线索探索发现遗漏」。**不破坏三层与两契约**——落在数据层新表 + 语义任务注册 +
> 薄编排视图。本节为契约草案：实现时字段若有变更，按惯例追加 CHANGELOG 工单。

**定位（一句话）**：一个工作台、两个模式——目标导向（串联工作区，解决聚合与串联）、
探索导向（放射导航，解决顺线索发现），共享数据层、双向过渡、路径可沉淀；
**模式是视图切换，不是启动分叉**——统一入口为一个搜索/输入框，输入后工作台同时呈现
聚合结果 + 线索编辑区 + 一键切放射视图。

**数据模型（DDL 草案，建表时随 schema canary 升版）**：

- `threads(id, name, note, created_at, updated_at)` —— 线索（串联主题工作区）：可命名、
  保存、复用的有序条目组；反复走的探索路径也可一键固化为 Thread（操作日志天然可复用）。
- `thread_items(id, thread_id, entry_id, position, relation_type, note)` —— 线索内条目与
  顺序；`relation_type` 开放枚举（seq 顺承 / because 因果 / prereq 前置 / contrast 对比…，
  首现定义、新增走 CHANGELOG）。
- 关联权重与解释：**不建新表**——条目↔分类挂接的 `confidence/origin` 即 weight/reason
  的既有形态（origin=prior/rule/llm/manual 已自带解释）；跨节点关联（关键字↔节点、
  条目↔条目共现）按需物化，约定带 `relation_reason`（如 `tag:对话描写`、`cooccur:3`、
  `llm_similarity:0.82`）——**没有解释的关联不展示**。
- 负反馈表：**设计预留，暂不建**——价值侧负反馈已由 `value_flag=ok`（否决判非知识）
  承担；关联侧负反馈待放射导航实装后按需追加（YAGNI）。
- `level_label`：节点带动态可读层级标签（大类/子类/条目/片段…），层级不硬编码四层——
  数据层按结构派生初值，语义层可细分；现有 graph/tree 节点的 `kind` 字段为雏形。

**语义任务（能力注册表新增项，互不依赖）**：

- `topic_recall`：输入主题/节点 id，多路召回聚合——FTS 命中、同分类路径共现、同 host
  聚类、显式关联、语义相似（LLM/embedding 可选）——输出条目列表，每条带 relation_reason；
  结果按来源与子主题分组。
- `thread_suggest`：输入某 Thread 的条目集，LLM 建议初始排序（概念→步骤→注意事项…），
  用户可调；结果落 `thread_items.position`。

**放射导航增强（在既有关系图三视图上迭代，不推翻——总览→搜索子图→子树下钻已是主干）**：

1. Top-N 渐进披露：每层默认只放射权重前 5–8 个节点，其余折叠展开（防毛球）；
2. 导航栈与面包屑：`关键字 › 集 › 簇 › 知识点`，点任一级回跳（防迷路）；
3. 边带 `relation_reason`（放射出去的每个节点能回答「为什么和当前焦点关联」）；
4. 双向反查：从知识点反查「哪些焦点能到达它」；
5. 空层降级：允许跳过空层级，不强行补空节点；
6. 路径固化：反复走的探索路径一键固化为 Thread。

**LLM 分工**：共现/标签统计纯代码；语义相似度与簇命名才调 LLM（先聚类再命名）；
`relation_reason` 由规则生成初值，LLM 润色为可选。

**原始会话线程还原（邮件 / AI 会话多轮，2026-10-20 第三十一批增补，契约草案）**：

> 来源：用户引文核查定调——邮件多轮来回与 AI 会话在结构上同构（同一主题多轮消息 +
> 引用关系，正文大量重复引用、增量信息只占小段），处理核心不是「去重」而是
> 「还原线程 → 引用剥离 → 增量压缩」。适配器只还原结构、不做压缩；压缩归语义层，
> 与来源无关。**不绑定外部讨论推荐的具体工具**（trimail 为 npm 单人小包不引入；
> Bichon 为 AGPL-3.0 重服务器，只借鉴其线程重建思想），Python 侧选型见 quote_strip。

- 概念区分（防混淆）：`threads` 表既有语义 = **用户串联线索**（curated）；原始会话线程
  = **源同步自动还原**（source）。同表不分表（结构同构、查询统一），增列
  `thread_type TEXT NOT NULL DEFAULT 'curated'`（建表时随 schema canary 升版）。
- 新表 `conv_messages(id, thread_id, entry_id, msg_key, parent_id, sender, sent_at,
  ordinal, quote_anchor)`（DDL 草案）：`msg_key` = 源内消息唯一键（邮件 Message-ID /
  AI 会话轮次 id）；`parent_id` = 线程内父消息（邮件按 In-Reply-To/References +
  Subject 归一化，AI 会话按 parent-id/顺序）；`quote_anchor` = 被引用消息 id（可空）。
  **本表只存结构与锚点，永不复制正文**——原文只在 entries/content_store（三层留存的
  原始层由既有架构天然保证：源文件只读 + content_store 按需缓存，均不删除）。
- 语义任务（能力注册表 §4.3 新增项，互不依赖、可独立关闭——纯规则降级模式同 Phase 4 探针）：
  - `quote_strip`（规则优先，不调 LLM）：每封邮件/每轮消息剥离引用与签名，产出
    「本轮增量正文 + 指向原文的锚点」。选型（2026-10-20 联网核实）：底座
    **mail-parser-reply**（PyPI，MIT，纯 Python 零依赖，v1.36 2025-12 仍维护，
    约 38 万下载/月，多语言回复头识别；其中文客户端格式标记为未验证——QQ 邮箱
    「在 … 写道：」等中文回复头规则自补）；**email_reply_parser**（Zapier port，
    仅英文启发式、2020 后停更）只借鉴其 fragment 模型不集成。规则覆盖 80–90% 即可，
    剩余允许人工补标（同 value_flag 人工否决风格）；原文永留，剥离错了也不丢信息。
  - `delta_summarize`（LLM，后置）：对剥离后的增量正文压缩为 1–3 句「本轮新增了什么」，
    原文指针保留；LLM 走 §6 [llm] 后端池（硅基流动优先、DeepSeek 官方兜底）。
  - `thread_digest`（LLM，后置，thread 层跑一次）：按「问题 → 关键进展 → 当前结论/
    待办」组织累积式摘要，不拼接各轮摘要。
- 视图衔接：线程视图（按轮次显示「谁、何时、新增了什么」+ 引用锚点，可回溯原文）挂入
  工作台与放射导航；`thread_digest` 产物可作簇节点挂分类树/放射图；`quote_anchor` 形成
  线程内关系边，`relation_reason='quote:<ordinal>'`（没有解释的关联不展示——同本节既有纪律）。
- 实施顺序纪律：先适配器结构还原（Phase 2/3）→ quote_strip 规则剥离 → LLM 摘要后置；
  摘要是压缩表示、原始层永在，不完美也不丢信息。

**优先级（用户 2026-10-20 定调）**：串联工作区 > 放射导航增强 > 词云/时间线。

**命名纠偏（术语规范）**：早期讨论稿中的 CLI `atlas` 与 `knowatlas.db` 为旧称
（本项目自定义稿，未实施）——实际以 `python -m knowatlas`（kinit/kadd/ksync/kcheck/
kexport/serve）与 `data/knowledge.db` 为准。

## 10. 错误分类与日志规范

### 10.1 错误分类（errors.py）

| 错误类 | 用途 | 同步时的行为 |
|---|---|---|
| `ContractError` | 字段/scheme/契约违例 | 该条目标记失败，继续 |
| `LocatorFormatError` | locator 不符合 scheme 规范 | 同上 |
| `UnknownSchemeError` | 未注册 scheme | 同上 + 日志 WARNING |
| `AdapterError` | 适配器读取源失败 | **跳过整个源**，其余源继续 |
| `AuthExpiredError` | 凭证失效（IMA/腾讯文档/exporter） | 跳过该源，消息含重取指引 |
| `RateLimitError` | 429 | 指数退避；超限跳过该源本次 |
| `DegradedParseError` | 可降级解析失败（.emmx page.bin、PDF） | 降级标题级，`degraded=true` |
| `ConfigError` | 配置缺失/非法 | 启动即退出（退出码 1） |

所有错误类继承 `KnowAtlasError`，携带 `entry_id: str | None` 与 `hint: str`（给用户的下一步动作）。

B站接口错误码映射（H7 返工定稿）：72010002 → AuthExpiredError（SESSDATA 失效，hint 含 F12 重新获取步骤）；-403 不一律判失效——先记录原始 code + message 再分类（也可能是权限/风控）；412 → RateLimitError（风控，降速重试）；视频下架判定看 `resource/list` 返回项的 attr 位（非标题为空），下架项保留标题级条目并记 meta.invalid=true。

### 10.2 日志规范

- 结构化 JSON 行：`{"ts", "level", "component", "run_id", "msg", ...上下文}`。
- component ∈ adapter / fetcher / semantic / datalayer / web / cli。
- 每次同步：start/finish 各一条 INFO，finish 带 stats（各源条目数、失败数、降级数）。
- 禁止打印凭证与正文内容；正文截断至 80 字符入日志。
