# 变更工单 · 点级勘误机制（P1）

## 1. 为什么

现有勘误是**条目级**：L1 确定性扫描 + L2 `errata_check` 把结论写 `entry.meta.errata_flag`，
队列 `/api/errata` 列条目。但 2026-10-25 全量实测表明，错误绝大多数发生在**点**这一层
（37 条 wrong 全是「把机制压成一句口诀」或「把特定实现说成普遍事实」），而一个条目里
多数点是正确的——条目级标记会连坐整篇（与点级老化裁决 #14 同一类问题）。

P1 的目标：点级事实核查成为机制——只吃 `kind=hard`（P0 分诊），结论落 `point.meta.fact_check`，
`wrong` 进裁决队列、`suspect` 只留筛选视图，**只标不删**。

## 2. 契约变更

| 项 | 变更 | 说明 |
|---|---|---|
| `points.meta` | **新增 1 组键** `fact_check = {verdict, reason, evidence, reason_code, at, model, stage}` | 不改表结构；`verdict ∈ {wrong, suspect, ok}`；`reason_code ∈ {fact_error, overclaim, ""}`；`stage ∈ {seed, llm}` |
| REST | **新增只读** `GET /api/errata/points?limit=` | 接口签名变更，故立本工单；只读、无写操作、走既有 Host/Origin 白名单中间件 |
| CLI `kerrata` | **新增参数** `--points`、`--from-json PATH` | 默认行为（L2 条目核查）不变；`--limit` 默认改 `None`（条目 10 / 点级不限） |
| 能力注册表 | **新增 `point_errata`** | 注册在 `registry/builtins.py` |
| datalayer | 新增 3 个点查询方法 | 唯一碰 SQLite 的模块红线 |
| 表结构 / `SOURCE_TYPES` / `STATUSES` / locator scheme / `CONFIG_SCHEMA_KEYS` | **无** | canary 前五项指纹不变；`capabilities` 因新增能力更新 |

## 3. 实现

### 3.1 `semantic/tasks/point_errata.py`（新增）

- 三值 `wrong` / `suspect` / `ok`；`wrong` 必须附 `evidence`（规范名/版本/官方文档 URL），
  给不出 → 自动降 `suspect`（§7.6 防幻觉纪律，复刻 `errata_check`）。
- `reason_code`：`fact_error`（事实/机制说错）与 `overclaim`（绝对化：必须/只能/始终/
  有且仅有，且原文无限定条件）分开记——实测 wrong 三大类正是机制说错、规格细节错、绝对化。
- `ctx.llm is None` → `llm_used=false`；`LlmError` → `error`；非法 verdict 丢弃。

### 3.2 `pipeline/errata_points.py`（新增）

`run_point_errata(cfg, dl, *, limit=0, dry_run=False, seed_path=None, batch=20, llm=None)`：

1. 候选 = `kind=hard` 且 `fact_check.at` 为空（领域闸门直接 import
   `pipeline/triage.py::is_hard`，不另写 SQL 口径）；`opinion`/`unjudgeable`/`dupe` 永不进入；
2. `seed_path`（`{point_id: {verdict, reason, evidence}}`）命中 → 确定性回放，`stage="seed"`，
   零 LLM；这是默认路径（当日 1,579 条 hard 已核）；
3. 剩余新点 → LLM 增量（20/批，与 `errata_check` 同口径）；LLM 不可用 → 整批 skip、不写半成品；
4. 结论落 `merge_meta_of_point({"fact_check": {...}})` + `log_task(..., "fact_check", ...)` 留痕；
5. 幂等：`content_hash` 为点 id + `fact_check.at` 游标，已核不重跑。

### 3.3 `datalayer/db.py`

- `hard_points_without_fact_check(limit=0)`：候选（含 meta）。
- `points_fact_check_counts()`：`wrong/suspect/ok/(none)` 验收口径。
- `points_wrong_queue(limit=500)`：队列 = `kind=hard` 且 `fact_check.verdict=wrong` 且
  `fact_check.dismissed` 非真（人裁误报后出队），按 `fact_check.at` 倒序。

### 3.4 `web/api.py`

`GET /api/errata/points`：只读，逐条附 `reason`/`evidence`/`reason_code`/`at` 与**溯源**
（`point_sources` → 条目 id/title/locator）。**不含 UI 页签**——页签渲染留 P1b，
本接口先供人工核查与后续前端消费。

### 3.5 `cli.py`

`kerrata --points [--from-json PATH] [--limit N] [--dry-run]`；与 `--scan` 互斥（退出码 2）。
报告打印 `wrong/suspect/ok` 分布与队列提示。

## 5. 回滚

```sql
UPDATE points SET meta = json_remove(meta, '$.fact_check');
```

实跑前备份 `data/knowledge.db` 到 `temp/`；命令可反复重跑。
