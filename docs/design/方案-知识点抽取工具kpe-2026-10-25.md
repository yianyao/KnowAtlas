# 方案：独立知识点抽取工具 kpe（2026-10-25）

> 目标：把"大文件（≥30 万字）→ 自包含知识点"做成一个**独立工具**，
> 既能用任意 OpenAI 兼容模型（HY3 / Space-Bunny / DeepSeek / 免费模型），
> 又能以后嵌进 KnowAtlas。先拿《AI Agents in Depth》中文版试跑。
> 本文只是方案，未写代码。

## 0. 结论

**借鉴现成工具的思路，自己写薄工具**（约 800–1,200 行），不引入
RAGFlow / Dify / GraphRAG / LightRAG 这类平台或框架。理由见 §5。

## 1. 为什么这本书适合做第一块试金石

| 事实 | 数值 |
|---|---|
| 页数 | 304 |
| 目录页 | 第 2–8 页（点线目录，含全部 295 条标题+印刷页码） |
| 正文起始 | 第 9 页「引言」；**PDF 页 = 印刷页 + 8**（已验证：第2章 29→37、第3章 70→78、第7章 177→185） |
| 正文字符 | 1,045,082 |
| 现有 markitdown 文本 | 无分页符（`\f`=0），目录混在正文开头 |
| 预计块数（TOC 合并到 ~6k 字） | **150–190** |
| 预计知识点 | 600–900（按 4–5 点/块） |

用户读过两遍 → 有现成的"应该抽到什么"的判断，是最合适的验收样本。

## 2. 工具形态

```
tools/kpe/                     # 独立包，不 import knowatlas
  kpe/
    __init__.py
    cli.py                     # kpe chunks / extract / review / stats
    pdf.py                     # pypdf 书签 + pdfplumber 按页取文
    chunk.py                   # TOC 优先分块；md 标题；纯文本窗口
    prompt.py                  # 抽取 prompt（v0）
    llm.py                     # OpenAI 兼容适配器（base_url/model/key/thinking/并发/重试）
    validate.py                # JSON 容错、quote 校验、最小自洽闸门
    store.py                   # JSONL + manifest + 断点续跑
    review.py                  # 按章节导出 Markdown 复核稿
  tests/
  README.md
```

CLI：

```bash
kpe chunks  book.pdf --out out/            # 只分块，产出 chunks.jsonl（可人工看）
kpe extract out/ --model X --base-url ... --workers 4
kpe review  out/ --top 50                  # 生成 review.md
kpe stats   out/                           # 块数/点数/失败/quote 命中/token
```

产物（`out/`，可整个拷走）：

- `manifest.json`：书元数据、TOC、分块参数、模型、时间、token 汇总
- `chunks.jsonl`：`{id, section_path, page_start, page_end, chars, text_hash, text}`
- `points.jsonl`：`{chunk_id, section_path, page, text, quote, quote_ok, model, usage}`
- `review.md`：按章分组，点 + quote + 页码，供人工抽检
- `cache/`：每次 LLM 响应原文（断点续跑；重跑不重复花钱）

## 3. 分块：TOC 优先（这本书的关键）

1. 用 **pdfplumber**（已是现有依赖，无需新增）读第 2–8 页目录文本，
   正则解析 `标题 + 点线 + 印刷页码`，得到 295 条标题与层级
   （`第X章`=L1、`X.Y`=L2、`X.Y.Z`=L3）；
2. **页偏移**：正文第 9 页是「引言」（印刷页 1），所以 `PDF 页 = 印刷页 + 8`；
   用「第 1 章」首次出现在正文的页校验偏移，失败则退化为标题匹配；
3. 按目录页码切节，节文本 = `pdfplumber` 逐页取文、拼接；
   每页先去掉重复页眉（"目录"/书名）、孤立页码行；
4. 合并过短节（< 800 字）到同父节；超长节（> 7,000 字）按段落切，
   留 10% 重叠；
5. `section_path = "第 2 章 上下文工程 > 2.4 提示工程 > 2.4.7 提示注入"`，
   附 `page_start/page_end`；
6. 跳过：封面、目录页、前言、致谢、思考题、本章小结（可配置）；
7. 无目录页的 PDF 退化：按字号/行首特征找标题（v2 再做），否则 6,000 字窗口；
8. MD 输入按 `#`–`###` 切节，代码围栏内的 `#` 不算。

为什么不用现成解析器：这本书自带印刷目录，`pdfplumber` 足够且宽松许可
（MIT），不引入 AGPL 的 MinerU；Docling（MIT）是"没有目录/版面复杂"时的
备选（v2）。

## 4. 抽取与校验

**Prompt v0 要点**：书名 + section_path + 页码 + 块序号；要求 1–6 条；
每条自包含（不出现"本章/它/该"）、一条一事、quote 逐字 15–40 字；
"逐段扫描，每段至少判断一次"；只输出 JSON。

**适配器**：任何 OpenAI 兼容端点（`base_url` / `model` / `api_key_env`），
可选 `thinking: disabled`、`response_format: json_object`、温度、并发
（默认 4）、429/5xx 指数退避、单次超时；记录每次 `usage` 与耗时。

**校验（不信任模型）**：

- JSON：去围栏 → 找首个 `{...}` → 失败则一次"修复重问"（带错误信息）；
- quote：两侧去空白/标点后做子串匹配；不中记 `quote_ok=false`，**不丢点**，
  交人工复核；
- 最小闸门：长度 10–500、不以"本章/本节/本文/作者/它/该"开头、
  不含"……"截断、不含点线目录、代码围栏闭合；
- 去重：同一本书内 `normalize(text)` 的 hash；可选 embedding 近重（后置）；
- 失败块：记 `status=failed`，`kpe extract` 重跑只补失败/缺失块。

## 5. 为什么"借鉴思路、自己写"，而不是直接用现成工具

| 选项 | 为什么不 |
|---|---|
| RAGFlow / Dify | 平台重（Docker、DB、前端），分块/抽取逻辑被平台锁住；改 prompt、断点、JSONL 产物都别扭 |
| GraphRAG / LightRAG | 输出是实体-关系图，不是"自包含知识点"；依赖重，中文书调优成本高 |
| LlamaIndex / LangChain | 只是库，仍要自己写分块/校验/续跑/复核；引入大依赖 |
| MinerU / Docling | 值得借"结构解析"这一层；但这本书有书签，pypdf 就够。Docling（MIT）可作无书签时的备选；MinerU（AGPL）内嵌需评估 |
| 自己写 | 核心只有 6 件事：解析、分块、prompt、校验、续跑、复核；约 1,000 行，全部可测、可嵌、可换模型 |

**借的具体经验**：GraphRAG 的"块大小 + 重叠 + 每块前置标题"、Docling
HybridChunker 的"按结构合并/切分 + 元数据"、Dense X 的"命题级自包含"、
Chroma 的"语义分块不划算"。

## 6. 与 KnowAtlas 的关系（后置，单独工单）

- `kpe` 不依赖 `knowatlas`；KnowAtlas 侧加一个薄适配：
  `pipeline/points.py` 对长文调用 `kpe`（作为库），把 `points.jsonl`
  映射成 `put_point(...)`（沿用 `quote` 锚点、`meta.section_path/page`）。
- 契约影响：**本工具阶段为零**；接入阶段只改 `pipeline/points.py`
  与新增可选依赖，不动表结构/字段/接口签名。

## 7. 分步与验收

| 步 | 内容 | 验收 |
|---|---|---|
| P0 | 包骨架 + pypdf/pdfplumber 解析 + TOC 分块 + `chunks` | 本书分出 150–190 块，章节路径/页码正确；单测覆盖合并/切分/跳过 |
| P1 | LLM 适配器 + 抽取循环 + 并发/重试 + 缓存 | 3 章跑通；断点续跑不重复调用；usage 落盘 |
| P2 | 校验 + 去重 + `review.md` + `stats` | JSON 合法率、quote 命中率、失败块可重跑 |
| P3 | 本书 3 章试点 → 用户抽检 → 调 prompt → 全书 | 用户按"读过两遍"的标准抽 50 条，≥80% 可用 |
