## 2. 方案

### 2.1 判据：按「客户端地址」判本机，不按 Host

`src/knowatlas/web/api.py` 新增两个纯函数：

- `is_loopback_client(request)`：`request.client.host` ∈ `{127.0.0.1, ::1, localhost}`；
  `request.client is None`（部分 ASGI 服务器/测试传输不填）时**回落**判 Host 头首段是否 loopback，
  两者都不确定 → 判非本机（fail-closed）。
- `write_cookie_allowed(cfg, request)` = `bool(cfg.get("web.allow_lan_writes", False)) or is_loopback_client(request)`。

为什么不看 Host：Host 已被白名单保证「合法」，但它只说明**你用哪个名字访问**，不说明**你从哪儿来**；
「同网段设备」的定义是来源地址。反代场景（P2 TLS）下客户端地址是反代自身（loopback），
届时若仍要求只读，把 `allow_lan_writes` 留在 `false` 也不够——这一点写进 §5 已知限制，由 P2 单独立项。

### 2.2 `/api/session`：只给本机（或显式开启时）种写 Cookie

`src/knowatlas/web/routers/admin.py::session`：

- `write_allowed = write_cookie_allowed(cfg, request)`；
- `write_allowed and tok` 才 `set_cookie(_WRITE_COOKIE, ...)`（HttpOnly / SameSite=Strict 口径不变）；
- 响应加 `"write_allowed": write_allowed`；`configured` / `fingerprint` / `cookie` 三个既有字段语义不变
  （`cookie` 仍表示「Cookie 名」，不再等价于「已种」——前端以 `write_allowed` 为准）。

### 2.3 写守卫：给 LAN 只读一条独立分支

`check_write_access`：token 校验失败后，若「没有携带任何凭据」且「来源是 LAN」且「未开 `allow_lan_writes`」，
返回 403 `FORBIDDEN_READONLY`，文案三条出路（回本机写 / 开 `allow_lan_writes` / 页面填令牌）。
其余情况仍走原 `FORBIDDEN` 文案（含令牌指纹），不放宽任何既有约束——
Host / Origin / content-type / token 四条全部原样。

### 2.4 前端：只读徽标 + 令牌兜底（不新增后端路由）

`static/index.html`、`static/thread.html`：

- `ensureSession()` 后若 `write_allowed === false` 且本地无令牌 → 顶栏出「只读」徽标
  （复用 `#offline-badge` 的 `.offline-badge` 样式，`title` 说明三条出路）；
- `writeJSON()` 在发请求前短路：`write_allowed === false && !token()` → 弹一次令牌输入
  （`ka.prompt`），存 `localStorage.knowatlas_token`，走既有 `X-KnowAtlas-Token` 头重试；
  取消则返回 `{__aborted:true}`（不产生半截写）。
- 错误响应带 `FORBIDDEN_READONLY` 时给可读提示，而不是把原始 403 文案糊到用户脸上。

### 2.5 配置示例

`config/knowatlas.example.toml` 的 `[web]` 增 `allow_lan_writes = false` 与注释
（默认只读、开它会放开什么、与 `server_host` 的关系）。`docs/参考-配置.md` 由
`tools/gen_docs.py` 重生成（150 行）。

### 2.6 serve 启动提示与配置同口径

`cli/cmd_ops.py` 在 `--host` 非 loopback 时原本打印「同网段设备打开页面即自动获得写凭据」——
本单之后这句只在 `allow_lan_writes=true` 时成立。改为按 `lan_writes_enabled(cfg)` 分两支：
默认说「同网段设备**只读**」并给开关路径；打开时说「改库不限本机」并提示改回 false。

### 2.7 顺带修的真 bug：`ka.prompt` 取消语义

`ui.js` 里 `#ka-cancel` 原来不分 mode 一律 `finish(false)`，而 `ka.prompt` 自己的约定是
**`null` = 取消**（docstring 写明），调用方 `.trim()` 直接 `TypeError`。
本单的令牌弹窗是第一个真正会走到「取消」的调用点，实测报文 `t.trim is not a function`。
改成 prompt → `null` / confirm·alert → `false`，两条调用方再补 `typeof t !== "string"` 中止。
加静态探针 `test_ui_prompt_cancel_resolves_null` 防回退。
（该 bug 属既有缺陷，非本单引入；修它是为了让「取消 = 什么都不发生」这条承诺成立。）

## 5. 已知限制

- 反代（P2 TLS）下客户端地址是反代本身，会被判为 loopback → 仍种 Cookie。
  要按「真实来源」收紧要读 `X-Forwarded-For`（可信代理才可读），属 P2 单独立项。
- `write_allowed` 只在页面加载时取一次；若中途改配置，需刷新页面（与 `server_host` 需重启 serve 同理）。
- 手机在 `http://<内网IP>` 下不注册 SW（非安全上下文），本条与 PWA 离线无关。
