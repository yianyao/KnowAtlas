# 变更工单 · KPE 产物导入适配器

## 1. 为什么

`tools/kpe`（v0.1.0，独立可安装包）已经把长书拆成自洽知识点，但入库一直靠
`temp/kpe_import.py` 这类一次性脚本：路径写死、清单写死、无幂等保证、无快照、无测试。
同时点层 `run_points_extract()` 对整本书走的是「integral 整条照抄」或「split 切点」，
与 KPE 的「分块抽取 + 逐字 quote」是两条不同口径，不能混用。

本工单把「KPE 产物 → 点层」固化成正式入口，供 `kpeimport` 子命令与后续批量调用。

## 2. 契约变更

| 项 | 变更 | 说明 |
|---|---|---|
| CLI 子命令 | **新增 `kpeimport`** | 接口签名变更，故立本工单 |
| 表结构 | 无 | 复用 `points` / `point_sources` |
| `SOURCE_TYPES` / `STATUSES` | 无 | — |
| locator scheme | 无 | — |
| `CONFIG_SCHEMA_KEYS` | 无 | 不新增配置键；canary 常量不变 |

点层 `meta` 新约定的固定键（写进点的 `meta`，供检索与复核）：

`extractor="kpe"`、`book`、`section_path`、`page_start`、`page_end`、`quote`、`model`、
`judge_reason`。`judge` 固定 `split`（KPE 点=切出来的独立知识点）。

## 3. 实现

新增 `src/knowatlas/pipeline/kpe_import.py`：

- `import_kpe_dir(cfg, dl, out_dir, *, entry_id, match, replace, dry_run, backup, limit) -> dict`
- 读 `<out>/manifest.json` + `<out>/points.jsonl`（**纯 stdlib**，不 import `tools/kpe`——
  KnowAtlas 保持可分发；换抽取器只要产物同格式即可复用）；
- 条目定位优先级：`--entry` > `--match`（标题/locator 通配，必须唯一命中） >
  `manifest.book` 与条目标题**精确**相等；0/多命中均报错并列出候选；
- 前置节点丢弃（目录/前言/序/致谢/关于作者/Contents…），与试跑脚本同名单；
- 幂等：`(point_hash, entry_id)` 已有溯源 → skip；
- `char_offset` 用 quote（缺则 text 前 40 字）在条正文里回填，找不到留 NULL；
- `--replace`：先 `purge_entry_points(entry_id, reason="kpe_replace")` 再导——
  只清该条目溯源与孤儿点，一点多溯源时仍被别处引用的点保留；
- 写库前 `snapshot(force=True)`（`--dry-run` / `--no-backup` 除外）。

`src/knowatlas/cli.py`：注册 `kpeimport` 参数与 `_cmd_kpeimport`。

## 4. 验证

- `uv run python -m pytest tests/test_kpe_import.py -q`（新测试：定位/丢弃前置/幂等/replace）；
- `uv run python -m pytest -q`（全量不回归）；
- `uv run python -m pytest tests/test_canary.py -q`（指纹未动，应仍绿）；
- 真实库：`kpeimport temp/kpe-aiagents-ch/ch-1 --dry-run` 先看统计。

## 5. 风险与边界

- **不删原文、不删条目**：只动点层；`--replace` 仅清该条目点溯源。
- **不校验点质量**：KPE 侧已有自洽性闸门（`kpe.validate`），本模块只做去重与落库。
- **quote 回填是尽力而为**：正文未抓取（content 为空）时 offset 为 NULL，检索靠点文本。
