# 变更工单 · P4 点级图

## 1. 为什么

关系图现在有三种焦点（分类 `c:` / 条目 `e:` / 域名 `d:`），第三层是**条目卡**（文件维度）。
但库里的知识早已是点层：4,552 个点、全部带 `book`/`section_path`，点向量 4,552 条
（`api:BAAI/bge-m3`，1024 维），点级检索（`/api/search`）与词云点 facet 都已点优先。
用户裁决（TODO P4）：**图要能看「知识之间怎么连」，而不是「文件之间怎么连」**。

现状的缺口：

1. 点只能出现在「🧠 主题」聚类视图里，且**冒充 `kind:"entry"`**（`_point` 标记）——
   点击不切焦点、也无理由边；
2. `radiate` 不认识 `p:` 前缀，点无法作为放射焦点；
3. 子树第三层固定出条目卡，看不到「同一章里的其他知识点」。

## 2. 契约变更

| 项 | 变更 | 兼容性 |
|---|---|---|
| 图节点类型 | 新增 `kind="point"`，节点 id 前缀 **`p:<point_id>`** | 纯新增；既有 `c:`/`e:`/`d:` 不变 |
| `GET /api/graph/subtree` | 新增可选查询参数 `layer=entries\|points`（默认 `entries`）、`point_limit=200`（夹紧 1–600） | 不带参数时行为与现在完全一致 |
| subtree 响应 | `layer=points` 且有点时返回 `"layer":"points"` + 点节点/边；否则回落条目层并标 `"layer":"entries"` + `"note"`；截断记 `truncated.points` | 老前端忽略新键即可 |
| 点节点字段 | `text`（前 300 字）、`path`（《书名》/章节）、`sources`（前 2–6 条溯源：entry_id/title/locator） | 纯新增 |
| `GET /api/graph/radiate` | `node_id` 接受 `p:<point_id>`；点焦点通道 `attach:<origin>` / `same_book:<book>` / `same_section:<book>/<section_path>` / `sim:<score>` | 纯新增；c/e/d 分支不动 |
| 表结构 / 字段 / `SOURCE_TYPES` / `STATUSES` / locator scheme / `CONFIG_SCHEMA_KEYS` / 能力注册表 | **无** | canary 常量应零漂移 |

**点节点消费面口径**（与既有消费面一致，不另立口径）：
`points.aging_flag != 'stale'`、`COALESCE(json_extract(meta,'$.dupe_of'),'')=''`、
且至少一条 `point_sources` 指向 `status='active'` 且通过 `_consumable('e')` 的条目。

## 3. 实现

### 3.1 `src/knowatlas/datalayer/db.py` —— radiate 点焦点

- `_RADIATE_KINDS` 增 `"p": "point"`。
- 新分支 `elif kind == "point":`
  - **focus**：`{"id":"p:<pid>","name":summary|text[:40],"kind":"point","text":text[:300],"path":"《book》/section","sources":[…]}`；
    `path` 无 book 时退化为 `溯源：条目名、…`。
  - **attach:<origin>**：`point_sources → entries → entry_categories`，按分类去重，节点带派生 `path`；
    origin 取首次出现的挂接来源（`rule`/`llm`/`manual`…），理由口径与条目焦点一致。
  - **same_book:<book>**：同 `meta.book` 的其他点，`created_at DESC`，理由带书名。
  - **same_section:<book>/<section_path>**：同书同章节的其他点；当 `section_path == book`
    （整本一块的 kpe 产物，如 Hello-Agents 820 点）时**不出该通道**，避免与同书通道重复。
  - **sim:<score>**：点向量 top 邻域，阈值 0.5（与条目 sim 同口径）；实现新增
    `_point_sim_channel()`，与 `_sim_channel` 同构（stdlib `array` 就地解码，不引 numpy）。
  - 所有通道按 `per_channel` 截断并累加 `truncated[channel]`；节点 `reasons[]`、边 `reason` 必填。
- 性能：4,552 点 × 1024 维纯 Python 余弦实测 **0.2 s**（解码 0.011 s + 点积 0.19 s），
  每次请求现算，不加缓存/不加依赖。

### 3.2 `src/knowatlas/datalayer/db.py` —— subtree 点层

`get_graph_subtree(category_id, limit, hierarchy, compact, layer="entries", point_limit=200)`：

- `layer="points"` 时，正常算出条目集（含 `hierarchy` 叶子分支与 `compact` 折叠口径）后，
  用 `point_sources` 把点接上来，第三层节点换成 `p:<pid>`（不再出 `e:` 节点），
  边 `p:<pid> → c:<cat>`、`kind="point"`（同一分类只连一条）。
- 点按 `point_limit` 截断，`truncated.points` 记剩余数；节点带 `text`/`path`/`sources`（前 2）。
- 该范围**没有可消费点**（新条目未抽点、点全 dupe/stale）→ 自动回退条目层，返回
  `"layer":"entries"` + `"note":"该范围暂无可显示的知识点，已回退条目层"`。
- 默认 `layer="entries"`，既有调用与测试零影响。

### 3.3 `src/knowatlas/web/api.py`

`/api/graph/subtree` 增 `layer: str = "entries"`、`point_limit: int = 200`：
非法 `layer` → 400（说明合法值）；`point_limit` 夹紧 1–600。其余端点不动。

### 3.4 `src/knowatlas/web/static/graph.html`（+ `tokens.css`）

- 新色令牌 `--point: #6FCF97`（深底对比 7:1 以上），`PAL.point` 运行时读取。
- 顶栏「◆ 点层」开关（`localStorage["knowatlas.graphPointLayer"]`，**默认开**）；
  `showSubtree()` 在开启时带 `layer=points`。
- `kind="point"`：尺寸 8、点色、标签规则（节点 ≤60 时显示）、tip 统计加分点数。
- 点击点节点 → `showRadiate("p:<pid>")`（放射模式内外一致，即「切焦点」下钻）。
- 节点卡：点节点显示正文 + `path` + 可点的溯源条目链接（补上「点层藏条目卡」后的原文入口）。
- 「🧠 主题」视图的点节点由 `kind:"entry"` 改为 `kind:"point"`，点击同样切焦点。
- `KIND_NAME` 补 `point:"知识点"`；`CHANNEL_LABEL` 补 `same_book/same_section/point/sim`。

## 4. 测试

新增 `tests/test_graph_point_layer.py`（约 10 例）：

- 点焦点：`focus.kind=="point"`；`same_book`/`same_section`/`attach` 通道出现；每节点 `reasons` 非空、每边 `reason` 非空；

- 无点范围回退 `entries` + `note`；API 非法 `layer` → 400；
- 前端静态探针：`pointLayer`、`kind === "point"`、`layer=points` 出现在 `graph.html`。

## 5. 验收

- 任取一点 `radiate p:<id>` → 邻域 **≥5** 且每条边有理由；在邻域里点一个点再放射（切焦点）
  两次仍非空图；真库只读探针记录点 id 与通道计数。
- `/api/graph/subtree?category_id=…&layer=points` 在 AI 书籍分类下给出点卡（节点数、截断数）。
- 浏览器 Ctrl+F5：点层开关生效；点节点点击切焦点；点卡显示正文、书籍/章节、溯源链接。
