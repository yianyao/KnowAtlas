# 变更工单 · P4 后置项：点级反查

## 1. 为什么

P4 点级图交付时把「点级反查」明确留空（P4 工单 §7、TODO P4「已知限制」第一条）：
`db.reverse_reach()` 只认 `c:` / `e:` / `d:`，**`p:` 落进 `else` 分支当分类查 → 分类不存在 → 404**。

图页这条路径是可达的：点层点节点一点就 `showRadiate("p:<id>")` 切焦点，此时再点「🔍 反查」，
`currentRadiate.nodeId` 就是 `p:…`，用户看到的是「该节点不支持反查（域名节点无反查）」——
提示词本身也说错了（点不是域名）。

放射视图能回答「这个点连到谁」，缺的是另一半：**「这个点是从哪来的」**——
哪篇条目包含它、哪条分类链能下钻到它。这正是点层可溯源（M7 目标）在图上的一跳入口。

## 2. 契约变更

| 项 | 变更 | 兼容性 |
|---|---|---|
| `GET /api/graph/reverse` | `node_id` 接受 **`p:<point_id>`**；返回 200 + `focus.kind="point"` | 纯新增；`c:`/`e:` 分支逐字不动，`d:` 仍 404 |
| reverse 响应 `items[]` | 新增两种来源：`kind="entry"`（**溯源条目**，`reason="source:point"`）、`kind="category"`（这些条目挂的分类，`reason="attach:<origin>"`，带 `path`） | 既有消费方按 `kind` 分支渲染，未知 kind 不炸 |
| reverse 响应条目项 | 新增**可选**字段 `locator`（仅点级反查的 entry 项带；前端有它才渲染外链） | 可选字段，缺省不出现 → 老前端行为不变 |
| 数据层 `reverse_reach` | 新增 `point` 分支；返回值形状不变（`{focus:{id,kind}, items:[…]}`），仍 `items[:limit]`（默认 20 / 上限 50 的夹紧在 `api.py`） | 纯新增 |
| 表结构 / 字段 / locator scheme / `SOURCE_TYPES` / `STATUSES` / `CONFIG_SCHEMA_KEYS` / 能力注册表 | **无** | canary 常量应零漂移 |

## 3. 判定与口径

**消费面（不另立口径）**：直接用 `_point_row(point_id)` 做闸门——它已包含
「`aging_flag != 'stale'` + 非 `dupe_of` 副点 + 至少一条溯源条目 `status='active'` 且过
`_consumable('e')`」。不满足 → `None` → 404。与 `radiate("p:…")`、`search_points`、
`get_point_hit` 同源，改口径必须四处一起改（既有红线）。

**只出非对称关系**：

| 放射（点焦点，已有） | 反查（本工单） | 理由 |
|---|---|---|
| `attach:<origin>` 分类 | ✅ 出「溯源条目挂的分类」 | 回答「哪条分类链能下钻到我」 |
| `same_book` / `same_section` / `sim` | ❌ 不出 | 对称边，反向就是把放射视图再列一遍；且两者已各有入口 |
| （无） | ✅ 出「溯源条目」 | 回答「谁包含我」——点层可溯源在图上的一跳 |

**排序与截断**：溯源条目在前、分类在后，均按既有查询顺序（`point_sources.created_at`），
最后统一 `items[:limit]`。

**分类去重**：多个溯源条目可能挂同一分类，按 `category_id` 去重，`origin` 取首次出现（与
`radiate` 的 `seen_cats.setdefault` 同写法）。

## 5. 不做什么

- **不做** same_book / same_section / sim 的反向枚举（对称边，重复放射视图）。
- **不做**「书」伪节点（`b:<book>`）：会引入新的节点 id 前缀，但 `radiate` 对它没有通道、
  点击没有去处——节点 id 是跨模块契约，不为一个面板新造。
- **不动** 反查面板对分类的既有行为（点分类名 → `showSubtree`）。

## 7. 已知限制

- 反查只覆盖「点 ← 条目/分类」一跳，**不含**跨书引用与指涉（`quote` 里的书名/编号引用）——
  那是 P4 第四类边（引用/指涉），需另写工单（规则先行 + 可选 LLM 复核）。
- 一个点的溯源条目超过 `limit` 时，分类项可能被条目挤掉（同属一个 `limit` 预算）；
  默认 20 对单点足够（实测单点溯源数多为 1–3）。
