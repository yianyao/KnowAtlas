# 变更工单 · 条目原文站内代理

## 1. 为什么

用户在图页按 Ctrl+F5 验收 P4 点级反查（提交 `93d6efa`）后报障：**「反查可溯源，但打不开」**。

定位（只读排查，2026-10-26 22:00）：

| 证据 | 内容 |
|---|---|
| 反查 API 实测 | `GET /api/graph/reverse?node_id=p:5c07508429801ddf` → entry 项 `locator="file://ai-agents-in-action-2nd-edition-cn-main/8.部署智能体与智能体系.md"` |
| 前端 | `graph.html` L690-692 把 `it.locator` **原样**塞进 `<a href>`；点卡 L241-251 早已守第三十七批纪律（非 http(s) 不出真链接），**反查面板漏守** |
| 真库 | `entries`（active 30 条）locator：**29 个 folder = `file://<相对 D:/sData/KnowLedge>`**（绝大多数 PDF）+ 1 个 `emmx://…` |
| 浏览器行为 | `file://` 后第一段被当**主机名**（无此主机）；且 http 页面跳 `file://` 被 Chrome/Edge 一律拦截 |

即：`file://` 是「配置根相对路径」的抽象写法（可迁移铁律），本来就不是浏览器能开的 URL。
真库 29/30 条原文都因此打不开——不是反查一处的问题，`index.html` 12 处条目链接同样是假的。

## 2. 契约变更

| 项 | 变更 | 兼容性 |
|---|---|---|
| `GET /api/entries/{entry_id}/file` | **新增**只读端点：200 流式返回原文；404 `NOT_FOUND`（条目不存在）/ `NOT_SUPPORTED`（非 file://，如 `emmx://`、`https://`）/ `FILE_MISSING`（根内找不到文件）；403 `OUT_OF_ROOT`（`..`/盘符绝对路径/解析后跑出根） | 纯新增；老端点与响应形状零改动 |
| 响应头 | `X-Content-Type-Options: nosniff` 一律加；PDF/图片/文本 `Content-Disposition: inline`，其余 `attachment` | 新端点自带 |
| `graph.html` | 新增 `rawHref(locator, entryId)`：http(s) 直开、`file://`+entry_id 走站内代理、其余返回空串（调用方退化纯文本） | 反查面板 / 点卡 / 条目点击三处统一 |
| `index.html` | 同上，新增 `rawHref` + `linkOrText`，替换 12 处「`href="${locator}"`」；预览面板「打开原文」同口径 | 列表观感不变，仅 href 变可打开 |
| 表结构 / 字段 / locator scheme / `SOURCE_TYPES` / `STATUSES` / `CONFIG_SCHEMA_KEYS` / 能力注册表 | **无** | canary 六项零漂移 |

## 3. 安全口径（为什么敢让浏览器通过 HTTP 拿本地文件）

1. **只读**：`GET`，零写库、零 LLM、不改任何状态（不写 `task_log`）。
2. **不新开面**：Host 白名单（`127.0.0.1:<port>` / `localhost:<port>`）与 Origin 校验已由中间件兜住；服务只绑回环。
3. **根内包含性**：`realpath(resolve())` 必须 `is_relative_to` 某个 `[sources.folders].roots`；`..`、反斜杠、盘符绝对路径在解析前就拒（403）。符号链接按解析后的真实路径判。
4. **不让浏览器执行站内脚本**：`.html/.htm/.svg/.xml` 若 `inline` 返回，会以 **本服务同源** 执行，能读走 `localStorage["knowatlas_token"]`（写令牌）→ 一律 `attachment` + `application/octet-stream`。Office/emmx 浏览器本来也渲染不了，同走附件下载。
5. **路径不回显**：错误响应只给相对串与理由，不回绝对路径（与 `/emmx_tree` 同纪律）。

## 5. 不做什么

- **不做** `POST /api/entries/{id}/open`（服务端 `os.startfile` 拉起本地程序）：等于给浏览器一个「在我机器上执行」的按钮，收益（用 Typora 打开）不如风险；站内 PDF 阅读器足够。
- **不改** `emmx://` 行为：脑图打不开是既知事实，已有站内大纲树（`/emmx_tree`）替代。
- **不改** `file://` locator 的存储形态（配置根相对路径是可迁移铁律）。
- **不做** 目录列表 / 任意路径下载端点：只服务「已有条目的主 locator」。

## 7. 已知限制

- 站内代理只覆盖 `[sources.folders].roots` 下的 `file://` 条目；书签/网页条目仍直开外部 URL（浏览器支持）。
- `file://` 路径含 `?` / `#` 的文件名会被 `urlparse` 截断（与 `file_reader` 同限制，真库无此类文件）。
- 大 PDF 走 `FileResponse` 流式发送，不做 Range 分片以外的优化；本地回环够用。
