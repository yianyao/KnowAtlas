# 变更工单 · 主题命名补第二词 + 合并迭代 + 检索结果主题聚合

## 1. 为什么（真库证据）

| 现象 | 证据 |
|---|---|
| `grpo（6 点）` / `grpo（4 点）` / `grpo（4 点）` 三簇 | 三簇讲的是不同侧面：**应用与 R1**（可验证 reward、2-GRPO）/ **定义**（无 critic、组归一化）/ **advantage 计算**（(r−µ)/σ、对 reward 尺度敏感）。两两质心 **0.805 / 0.825 / 0.838 < 0.85** → 确实没到合并线 |
| `mcp（12/17/9/2 点）` 四簇 | 12=定义与生态、17=Host/Client/Server 架构、9=stdio/SSE 传输、2=FastGPT/FastMCP；17 与 9 事后质心 **0.886 ≥ 0.85 却没并**——单遍贪心只在「插入时」比一次，之后簇心被后续合并拉动（`temp/topic_merge_debug.py` 复现） |
| 名字为什么一样 | 命名只用 100% 覆盖的共享词；这些簇的成员只共享 `GRPO`/`MCP` 一个词 → 只能 `GRPO（N 点）`，N 不同所以连 ② 去重都不触发 |
| 顺带发现伪词 | `体应·智能`（×3）：jieba `extract_tags` 会吐出跨词边界的 `体应`（来自「智能体应…」），当前只做「子串在每篇出现」校验，挡不住 |

## 2. 契约变更

| 项 | 变更 | 兼容性 |
|---|---|---|
| `/api/graph/topics` | **新增可选** `q`（点 FTS 检索过滤）、`category_id`（分类子树过滤）、`points_limit`（q 召回上限，默认 300，夹 20–2000） | 都不传 = 全库口径，R12 行为不变 |
| 响应 | **新增** `scope: {q, category_id, mode, points}`（本次聚合的点域） | 纯新增字段 |
| `topics[].name` | 第二词从「必须 100% 覆盖」放宽到 **≥60% 覆盖**；所有候选词必须通过 **jieba 分词 token 校验**（滤 `体应` 类跨边界伪词） | 仅字符串变化；搜索/高亮按子串，不受影响 |
| `_merge_clusters` | 单遍 → **迭代到不动点**（最多 5 轮，numpy 矩阵化的 `U[:k] @ unit`） | `merged`/`merged_from` 语义不变，`total` 可能再降 |
| 表结构 / 字段 / locator scheme / `SOURCE_TYPES` / `STATUSES` / `CONFIG_SCHEMA_KEYS` / 能力注册表 | **无** | canary 六项零漂移 |

## 3. 方案

1. **命名**（`graph_topics._topic_name`）：`_name_words(texts, coverage)` 统一出词——
   jieba 抽词 topK=20 → `word_ok` → 覆盖率 ≥ coverage → **token 校验**（`jieba.lcut` 里出现过）
   → 按覆盖率降序、最佳位置升序。命名规则：2 个 100% 词 `a·b`；1 个 100% 词 + ≥60% 第二词
   `a·b`；只有 1 个词 → `a（N 点）`；0 个 100% 词但有 ≥60% 词 → 同规则降级；全无 → `主题（N 点）`。
2. **合并**（`_merge_clusters`）：每轮按点数降序做一次质心贪心（矩阵化），有合并就再来一轮，
   直到无变化或 5 轮——修「先比后漂」。成本：真库单轮 ~0.3 s（矩阵乘）而非 1.3 s（逐点积）。
3. **检索聚合**（`web/api.py`）：`q`/`category_id` 先算点域：
   - `category_id` → `subtree_category_ids` → `entries_in_categories` → `points_of_entries` 取点 id；
   - `q` → `search_points(q, limit=points_limit)` 取点 id；
   - 两者都给 → 交集；都不给 → 全库。
   再把点域交给 `topic_clusters(point_ids=...)`（聚类/合并/命名完全复用）。
4. **前端**（`index.html`）：检索工作台加第 4 个 tab「主题」——拉
   `/api/graph/topics?q=<q>&limit=30`，主题行（名字 · N 点 · 合并 k 簇）可展开成员点，
   点「溯源：条目名」调既有 `openPreview`；换关键词即重取。

## 4. 验证

- `pytest tests/test_graph_topics.py`（新增：第二词补齐、伪词过滤、合并不动点、点域过滤）；

**两处实现坑**（已写进注释）：

1. `jieba.lcut` 也把 `体应` 切成词（posseg 标成名词），token 校验挡不住；改成
   「2 字纯中文必须在 `jieba.dt.FREQ` 词典里」，`智能体`（3 字 HMM 词）与 `GRPO` 不受影响。
2. 命名原来对同一批文本抽两遍词（100% 与 60% 各一次）；改成 `_name_candidates` 一次抽词
   出两档，80 个主题命名仍要约 2.4 s（`extract_tags` 是热点），端点总耗时 4.9 s。
