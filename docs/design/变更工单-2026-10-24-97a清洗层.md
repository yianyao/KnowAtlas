# 变更工单 · 批 97a 通用清洗段

## 1. 要解决的问题（真实数字，非推测）

样本验证（31 文件 / 5.9 M 字符）测出的噪音占比：

| 噪音类型 | 实测 |
|---|---|
| 纯页码/罗马数字行 | `agentic-design-patterns` **1,343 行（占 11%）**；`agentic-ai-guide` 769 行 |
| 目录点线行（`. . . .`） | `agentic-ai-guide` **994 行**；`agentic-design-patterns` 273 行 |
| 推广/署名尾 | `Obsidian-AI` 17 行；`Harness-Engineering` 12 行（花叔公众号/知识星球） |
| 导航文件当知识 | `navbar.md` / `sidebar.md` 已被收录为条目（0 正文） |
| 点层后果 | 18 个点全部 4023 字、全部以封面+目录开头 |

结论：不清洗，点层拿到的第一段永远是垃圾——这就是「以文件组织」的物理来源。

## 2. 验收目标（可量化）

1. 新抓正文：页码行 **0**、目录点线行 **0**、重复页眉页脚 **0**、推广尾 **0**。
2. 正文保留率 ≥ **97%**（按非空行计，扣除上述噪音后的正文行不得减少）。
3. `clean_common` **幂等**：`clean(clean(x)) == clean(x)`。
4. 代码块 / 表格行 / 列表项 **零误删**（用例固化）。
5. 误杀闸门：若删除行数超过 `min_keep_ratio` 上限，**保留原文**并记 WARN（宁可不洗，不可洗坏）。
6. 既有契约不变：条目不减少、点层照旧、检索字段不变。

## 4. 逻辑：规则清单（每条给判据 + 防误杀）

| 规则 | 判据 | 防误杀 |
|---|---|---|
| **R1 页码行** | 独立成行的 `^\s*([ivxlcdm]{1,7}|\d{1,4})\s*$`（忽略大小写） | **自适应**：仅当全篇此类行占比 ≥ **2%** 才整体删除；低于 2% 视为数据/编号列表，不删 |
| **R2 目录块** | 含 `\. \. \.` 或 `…` 且末尾带数字的行；自 `目录` / `Contents` 起的连续块整块删 | 需 ≥3 处点线特征；无特征不处理 |
| **R3 重复页眉页脚** | 长度 ≤ 40 且**完全相同**出现 ≥ 3 次 → 只保留首次 | 表格行（`|` 开头）与代码块内不适用 |
| **R4 推广尾** | 最后 25 行内命中 `公众号|知识星球|B站|YouTube|小红书|X/Twitter|官网|Created by|仅供学习参考` 的连续段 | 单次删除 ≤ 全文 **5%**，超出放弃 |
| **R5 空白归一** | 连续 ≥3 空行 → 1；行尾空白；零宽字符；连续分隔线（`---`/`===`）去重 | 不动缩进（代码块缩进有意义） |
| **R6 导航文件** | 非空行 ≤ 12 且 ≥60% 行是链接/列表项、无句读 → 整篇判非知识 | 只返回 empty + flag，由既有 L0 打 `not_knowledge`，不新增删除语义 |
| **R7 保护** | ```` ``` ```` 代码块内一行不动；表格行只做空白归一 | 规则实现上先切块再逐块清洗 |
| **R8 redact** | 手机号、身份证、邮箱、`sk-…`/`AKIA…` 形态密钥 → 掩码 | 默认开启；`[clean].redact_enabled=false` 可关；命中数进 meta 统计（不落原文） |

**阈值默认值**（`CleanThresholds`，测试可注入）：
`page_number_ratio=0.02`、`toc_min_dot_leaders=3`、`repeat_max_len=40`、`repeat_min_count=3`、`promo_window=25`、`promo_max_ratio=0.05`、`min_keep_ratio=0.90`。

## 5. 收口点为什么放在 sync（而不是各自 fetcher）

现在正文入库有 4 条分散路径（`_fetch_missing` 一处 + 3 处适配器 inline 落库），各自算 hash。
只要有一条漏洗，库里就会出现"洗过"和"没洗过"两种正文，后续点层无法解释。
→ 新增单一收口 `_ingest_content()`：**清洗 → 脱敏 → SHA-256 → put_content → _apply_content**，
所有路径必须经过它；`content_hash` 一律用清洗后文本计算（否则同一篇文清洗前后两条记录）。

2. **97a-2** `sync._ingest_content` 收口 + 4 处替换 + `[clean]` 配置 + canary 指纹 → 全量 pytest 绿；
   灰度验证：`[clean].enabled=false` 时行为与现在**逐字节一致**（回归用例钉住）。

| 项 | 变化 |

## 9. 风险与回滚

- 最大风险是 R1 误删"数据行里的独立数字"：用**全篇占比自适应**（<2% 不删）+ `min_keep_ratio` 双闸门。
- 回滚：`[clean].enabled = false` 立即回到当前行为；已清洗内容重灌即可复原（原文始终在源文件里）。
- 不做：给每篇保留"清洗前原文"副本——会翻倍占库，且原文可随时从源重抓。

## 10. 两处**对原方案的偏离**，需要你确认

1. **trafilatura 换装移出 97a**（原方案把这步算在 97a）。理由：换 HTML 抽取器会同时改变"进来的正文"和"洗掉的噪音"两个变量，出问题无法归因。建议 97a 只做规则清洗，换装单列为 97a+，用同一批样本 A/B 对比。
2. **IMA 接入验收顺延**（原方案评审建议 97a 顺带验 IMA）。理由：本机没有 IMA 凭证（`KNOWATLAS_IMA_CLIENT_ID` 未设），现在验不了；顺延到 8.12，不阻塞 97a。

> 确认这两条 + 认可 §4 的规则与阈值，我就按 §6 的三步开工。
> 若某条规则你不认同（例如不想删推广尾、或页码阈值想调），直接说，我改工单再动手。

## 11. 落地回填（2026-10-24，实施后补记）

用户回复「认可」（两条偏离均认可）后实施。三步全部完成，与工单的三处偏差如下：

| 工单项 | 实际落地 | 为什么改 |
|---|---|---|
| §4 R3 重复页眉页脚：≤40 字、完全相同 ≥3 次 | **三重判据**：像散文（4–40 字、≥2 汉字或 ≥6 字母、不以代码符号结尾）+ **行距周期性**（间隔变异系数 ≤0.45）+ **非结构性**（单行 ≤ 全篇 2%） | 第一版把 `)`（235 次）、`}`（180 次）、三引号（216 次）当页眉删，`agentic-design-patterns` 保留率 0.856 被闸门拦下——整本书等于没洗 |
| §4 阈值 `min_keep_ratio=0.90` | **0.80** | 页码重的书正常删 10–15%，0.90 会把"洗对了"判成失败；0.80 仍能挡住规则失控 |
| §5 收口：4 条路径统一走 `_ingest_content` | 抓取路径走 `_ingest_content`（清正文 + 重建 inline）；适配器路径（mail/session/emmx）走 `_store_bodies`（**只清正文库、不动 inline**） | 邮件 `inline_content` 是去引用的增量摘要，用全量正文重建会破坏既有契约（`test_maildir` 当即失败） |

**验收实测**（20 份真实正文 / 105,846 行）：噪声 4,896 行（页码 2,578、目录 1,555、重复行 751、推广 10、目录标题 2），
正文行保留率 **0.9999**；目标文件全部达标（`agentic-design-patterns` 页码 1,347→0、目录 273→0；
`agentic-ai-guide` 目录 994→0；`Harness`/`Obsidian-AI` 推广尾→0；`雪花写作法` 零删除）。
5 篇 PDF 各留 ≤1% 低占比独立数字行——**按阈值设计保留**，留 97b 用页边界再收。

**测试**：`tests/test_clean.py` 27 例；全量 `508 passed / 1 skipped`；canary `config_keys` 指纹已更新（本工单授权）。
