# 变更工单：点级去重误并修法（规则挑边界对 + LLM 裁定）

- 日期：2026-10-29
- 触发：R28 人工复核发现 5 对「同一句式里的不同事实」被 `dedup_points`（余弦 ≥0.92）误并，已手工撤销；
  R30 复测确认**下一次 `ksync --embed` 会再并 6 对同类误并**。用户 2026-10-29 裁决：走「规则挑边界对 +
  LLM 裁定」（不是提阈值，也不是数字/否定词一刀切）。
- 关联：批次 94（`pipeline/embed_index.py::dedup_points` 首版）、R28（误并复核与撤销）、
  `pipeline/triage.py`（LLM 增量 + 幂等 + 「不写半成品」的编排范式）、
  `semantic/tasks/point_triage.py`（task 骨架范式）

## 1. 现状（真库实测，2026-10-29）

`temp/probe_point_sim_pairs_20261028.py`（5,535 点参与，跳过 72 条副点/老化；float32 归一化后全量矩阵乘）
与 `temp/probe_existing_dupe_pairs_20261028.py`：

| 事实 | 数字 |
|---|---|
| 唯一对余弦 ≥0.90 / ≥0.92 / ≥0.95 / ≥0.97 | 65 / **6** / 1 / 0 |
| 这 6 对里误并 | **6 / 6**（labuladong 动态规划：`k=1` vs `k=2`、`碎了` vs `没碎`、`O(k^n)` vs `O(k*2^n)`） |
| 既有真重复的最低余弦 | **0.9174**（快速排序「代码框架」vs「递归框架」） |
| 误并候选的最高余弦 | **0.9607**（两种穷举角度） |
| 既有 72 对合并里带「数字/否定词差异」的 | **28**（多为真重复：`dp[i]` 初始值、不仅…也、`[1..i-1]`） |

三条判据结论：

1. **提阈值不是修法**：真重复最低 0.9174 与误并最高 0.9607 区间重叠；0.92→0.95 仍并掉 0.9607 那对，
   0.97 则全库去重失效（≥0.97 唯一对 = 0）。
2. **「数字/否定词差异就拒绝」也不行**：一刀切会误伤既有 72 对里的 28 对真重复。
3. 因此把「相似度」与「是否同一知识」拆开：embedding 只负责**召回候选**（宁多勿漏），
   规则负责**挑出需要裁定的边界对**，LLM 负责**裁定**；LLM 不可用/失败 → 边界对**一律不并**（宁漏勿误，
   与 `_DEDUP_THRESHOLD` 注释的既有口径一致）。

## 2. 方案

### 2.1 新增 `pipeline/dupe_guard.py`（纯规则，零 IO 零 LLM）

```python
def risk_signals(a: str, b: str, *, length_ratio: float = 1.5) -> list[str]
def is_risky(a: str, b: str, *, length_ratio: float = 1.5) -> bool
```

信号（命中任一即 `risky`，宁多挑不漏挑）：

- `数字差异`：ASCII 数字 token 多重集不同（`k=1` vs `k=2`、`O(k^n)` vs `O(k*2^n)`、`[1..i-1]` vs `[i+1..n]`）；
- `否定词差异`：`不/没/无/非/否/未/禁止/避免/切勿/别` 在一条里出现、另一条里没有（`碎了` vs `没碎`）；
- `长度比`：`max(len)/min(len) ≥ length_ratio`（一条是另一条的扩写：`dp[i]` 有无「初始值为 1」）。

为什么不做「去掉数字/否定词后比对残文」的更强规则：误并对的残文差异也很大（`从数字角度穷举` vs
`从桶的角度穷举`），强规则挑不出来；而规则的作用只是**缩小 LLM 判定面**，不需要高精度。

### 2.2 新增 `semantic/tasks/point_dupe_judge.py`（能力 `point_dupe_judge@1.0.0`）

- 签名（沿用 §4.3 批处理范式）：`run(items, ctx)`，`items=[{"pair_id","a","b"}]`，
  返回 `{"verdicts": {pair_id: {"same": bool, "why": str}}, "llm_used": bool, "error": str?}`；
- prompt 明确区分「数字只是书写格式差异」（判同一：`[1..i-1]` 共 i-1 层 / `dp[i]` 有无补充说明）
  与「数字/否定构成不同事实」（判不同：`k=1` vs `k=2`、`碎了` vs `没碎`、复杂度上界不同）；
- 纪律与 `point_triage` 一致：`ctx.llm is None` → `llm_used=false` 不抛；LLM 故障 → 返回 `error`，
  调用方**整批不写库**；非法/越界编号丢弃（宁漏勿错）。

### 2.3 `pipeline/embed_index.py::dedup_points` 增两个**可选**关键字参数

```python
def dedup_points(dl, threshold=_DEDUP_THRESHOLD, *, llm=None, dry_run=False) -> dict
```

- 聚类仍走 `_greedy_clusters`（向量召回，**不变**）；
- 每个簇内 (best, member) 逐对过 `dupe_guard.is_risky`：
  - 不 risky → 与现在**逐字相同**地合并；
  - risky → 进 `pending`，不立即合并；
- 聚类跑完后，`pending` 按 ≤20 对/批交给 `point_dupe_judge`：
  - `judge=None`（LLM 未启用）或 task 返回 `error` → **全部不并**（`vetoed_no_llm` / `judge_errors` 计数）；
  - 判 `same=true` → 合并；`same=false` → 不并（`vetoed` 计数），并把该对写进 `task_log`（可审计：
    「为什么这两条没并」）；
- `dry_run=True`：只算不写（`merge_meta_of_point` / `task_log` 都不落），用于真库彩排；
- 统计键：旧键 `groups` / `dupes` / `vectors` / `threshold` **保持**（CLI 打印与既有测试依赖），
  新增 `risky` / `judged` / `vetoed` / `vetoed_no_llm` / `judge_errors` / `dry_run`。
- 不做判定缓存：边界对当前只有 6 对（1 次 LLM 调用/轮），缓存会引入「点内容不变但结论过期」的
  隐患；等边界对增长到百级再立项（记 TODO 在本工单 §6）。

### 2.4 `cli/cmd_sync.py` 注入 LLM

`dedup_points(dl)` → `dedup_points(dl, llm=LlmClient.from_config(cfg))`（`from_config` 返回 `None`
时就是「无 LLM → 边界对不并」）。`ksync --embed` 输出里 `dedupe` 段会带上新计数。
