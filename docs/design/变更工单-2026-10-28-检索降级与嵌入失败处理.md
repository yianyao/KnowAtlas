## 2. 方案

### 2.1 `semantic/embed.py`：失败分类 + 失败闸

- `_encode_batch` 区分错误类型：
  - `httpx.HTTPStatusError` 等 4xx（**除 429**）→ 立即 `raise RuntimeError`，不重试；
  - 5xx / 超时 / 网络异常 / 返回条数不符 → 维持现有 `retries` 次退避重试。
- 新增模块级失败闸 `_FAIL_GATE`（键 = `(url, model)`，TTL 60 s）：
  - 某后端刚失败过 → 冷却期内再次 `encode` **直接抛同一原因**，不发 HTTP（把每次搜索的 11 s 降到 0）；
  - 冷却到期自动重试（充值后无需重启 serve 即自愈）；
  - 导出 `reset_failure_gate()` 供测试重置，避免跨用例污染。
- 为什么放在 `RemoteEmbedder` 内部而不是端点：`FakeEmbedder`（测试）与 `LocalEmbedder` 不受影响，
  闸门语义只属于「会走网络的远端后端」。

### 2.2 `web/routers/discovery.py`：语义通道降级，不阻断主通道

- `search()`：点融合（`search_points_hybrid`）与 `mode=hybrid`（`hybrid_search`）各自包
  `except Exception` → 降级为纯 FTS 结果，响应追加**可选**键 `embed_note`（如
  `"语义通道不可用（embedding 402），已降级全文检索"`），`effective_mode` 照旧 `"fts"`；
- 语义通道是加成项：FTS 点 + 标题直击 + 点反查条目必须照常返回；
- `mode=hybrid` 已有 `embedder=None` 降级分支（`note` 键），失败路径复用同一形状，避免前端两套判断。

### 2.3 `web/static/index.html`：故障可见，不再静默

- 三处 `fetch` 改成先查 `r.ok`：非 2xx 记录 `fails.push("search:" + r.status)`，
  并在结果区顶部渲染一条提示「⚠ 检索接口 HTTP 500，已用其余通道结果」；
- 响应带 `embed_note` 时渲染「⚠ 语义通道不可用，已降级全文检索」；
- 正常情况下（`r.ok` 且无 `embed_note`）DOM 与现版本逐字一致。

     带 `embed_note`；
   - `GET /api/search?mode=hybrid&q=雪花` → 200，`effective_mode=fts` + `note`；

5. 浏览器 Ctrl+F5：搜「雪花」出知识点卡片 + 顶部黄条「语义通道不可用，已降级全文检索」。

## 5. 不做（本轮明确排除）

- 不在端点里做 embedding 后端 failover（DeepSeek 无嵌入接口，本地 bge-m3 需 torch + 2.2 GB，
  属「换后端」决策，等用户裁决）；
- 不补向量（`ksync --embed` 依赖可用后端，402 未解决前跑了也是全失败）；
- 不改 `search_points` / `search_fts` / `search_entries_direct` 的匹配口径——本轮零结果差异。
