## 2. 继承的硬约束（浓缩版，逐条标来源）

**格式纪律**（std 规范 8 / 05 §4）
1. 全部落盘文本 UTF-8 无 BOM + LF；写文件显式 `newline="\n"`；收尾字节扫描 `b'\r\n'` 确认。
2. 禁止 PowerShell `Set-Content -Encoding UTF8` 写源码/文档（带 BOM，症状隐蔽）。
3. 脚本只依赖标准库（进 src/ 前先判依赖等级；第三方依赖只在 requirements 两份清单里）。
4. .gitattributes 锁 `* text=auto eol=lf`（例外 `*.cmd/.bat` CRLF、二进制清单）。

**变更流程**（std 规范 7 / 用户变更工单铁律）
5. 改文件先写工单（旧→新摘要 + 复检探针）；改后探针全命中才关单。工单工具用 复用区/agent-scripts/ticket.py。
6. 新增文件过出生检查单（frontmatter 合规、索引登记、关联件扫描、触发影响）；删除前 Grep 引用清零。
7. 同一文件多次修改禁并行（std 规范 9）；替换脚本匹配串一律从文件原文复制，不凭记忆重打（2026-10-19 实测踩坑）。

**记忆与状态**（std 规范 10 / 05 §3）
8. AGENTS.md 只放跨会话成立的约定；状态现场取（基线真跑、提交号现取）；交接文档第一屏=状态快照。
9. 读回验证后才声称完成（"我现在读到了"才是证据）。
10. 探针证据化：文档里的命令要被测试真跑；不能失败的断言等于没断言（先红后绿）。

**可迁移四律**（05 §6，脚本强制级）
11. 路径一律项目根相对；运行数据不出根；禁硬编码用户名/盘符（pre-commit grep 强制）；机器配置留 env 覆盖口；判据=新机新用户名按文档原样跑起来。

**授权与上下文**（std 规范 5/6）
12. 不跨出用户指定范围；范围外只读不动；误改第一动作=找备份无损还原。
13. 长任务上下文快满立即告知；先落盘留痕再建议开新会话。

**session-harvester 既有纪律**（适用本工程的摘录）
14. 测试基线必须串行跑，跑套件时不得并发编辑仓库（两次"假红"的根因）。
15. 收尾三件套：死代码扫描（AST，复用区/harvester-reuse/deadcode.py 解耦后用）+ 悬空路径检查 + 过期文本扫描。
16. 外部校验器只是最低门禁；完成判定 = 格式字节扫描 + 行为探针复检全命中。

### 2.1 门禁分层（2026-10-19 对比 specSkill 后定稿）

对比结论：specSkill 的**提交门禁**（`skillverify hook install` 装 pre-commit + CI workflow 兜底）比本项目原规划（仅本地 pre-commit 跑 check_crlf + grep 四律）成熟，**采纳其三层结构**；但其**没有工单要求**（等价物是"新增规则/命令固定动作"清单 + 交接文档对账守卫），本项目的工单流程（Agent_std 规范 7 + ticket.py）保留，二者互补不冲突。

1. **本地 pre-commit（轻量、快）**：check_crlf（CRLF 字节）+ grep 可迁移四律（用户名/盘符/绝对路径）——秒级，不拦长测试。
2. **CI 兜底（不依赖记性）**：specSkill 的判断成立——"本地 hook 只能拦住记得装且没加 --no-verify 的提交；换机器、换人、绕过 hook 时门禁形同虚设"。推 GitHub 触发 pytest + canary（TODO Phase 0 已补此任务）。
3. **判定分级语义**（借 specSkill 不变量 4）：FAIL 阻断 ｜ WARN 人工甄别 ｜ SKIP=未执行（计退出码）｜ INFO=不适用；**SKIP 永不伪装成通过**；豁免必须显式带理由（对应 ticket 工单的偏离记录），绝不静默放过。
4. **hook 安装纪律**（借 install_hook 实现）：幂等安装、遇非本工具 hook 默认拒绝（force 才先备份覆盖）、装完当场验兜底命令——"装了等于没装"必须当场说出来。

## 3. 过程文件落盘纪律（temp —— 用户 2026-10-19 明令，05 模板新增项）

1. **定义**：过程文件 = 不影响最终产物功能、不随最终产物迁移的一切文件——探针脚本、patch 脚本、中间报告、一次性验证件、工单草稿、比对草稿、字节扫描输出。
2. **落盘点唯一**：`<工作区>/temp/`（本工程 = `C:\Users\yianyao\WorkBuddy\记录树\temp\`）。**禁止**散落项目根（05 §2.5：代码本体不允许散落一次性脚本）、禁止散落 handoff/（那里只放正式交付文档与已关单工单）。
3. **结论回写**：temp 里只有过程没有结论；任何判断、数字、状态必须另写进已提交的文档（AGENTS.md / docs/design/ / 台账），temp 清空不损失任何知识。
4. **不进 git**：temp/ 在 .gitignore 清单里（若位于仓库根内）；兄弟目录形态天然在外。
5. **清理自由**：可随时整目录清空，不承担记忆职责。
6. **对 05 模板的增量**：05 §2 布局中无 temp/ 目录；本工程新增此约束并已回写 git-templates/.gitignore 注释。

## 6. 依赖与轮子集成策略（团队协作定稿，回答"自取还是先扔复用区"）

**两类分治**：

| 类别 | 判定 | 处理 | 谁维护 |
|---|---|---|---|
| A. 自研/改造件 | 本工程写出来的、或从既有项目解耦改造的（agent-scripts 六件、stopwords_zh.txt、参考实现四件、git 模板） | **进复用区**（唯一真相源），开发者从这里复制，不回源头重拷、不各自上网找版本 | 复用区 README 登记表 |
| B. 公共第三方件 | pip/clone 即得的成熟开源（httpx、fastapi、markitdown、wechat-article-exporter、readability-lxml、jieba、cytoscape.js…） | **不进复用区**，进**依赖清单**：Python 包 → requirements-core.txt / requirements-optional.txt **版本锁定**；非 pip 工具（wechat-article-exporter 等）→ 文档写明仓库地址 + 锁定 commit/版本 + 用途 + 获取命令 | 依赖清单文件（Phase 0 建） |

**理由**：
1. B 类复制品只会腐烂——版本漂移、安全更新都跟不上上游；pip/clone 一条命令即得，预存一份毫无收益。
2. A 类复制到复用区是因为"网上拿不到"或"是改造过的"——只有复用区能保证团队拿到同一份。
3. wechat-article-exporter 依赖微信扫码登录态，本来就必须各人自己操作；预先扒一份到复用区解决不了任何问题。
4. 版本漂移防线在**依赖清单的版本锁定**（如 `httpx>=0.28,<0.29`），不在文件预存。

**执行规则**：
1. 开发者需要 B 类件 → 按依赖清单命令自取；取不到（网络/版本消失）→ 报告，由负责人决定是否升版本或把该件转为 A 类（fork 后进复用区）。
2. 借鉴 B 类实现后的自研成果 → 按 §7 规则 4 回填复用区。
3. 复用区 README 是 A 类件的唯一索引；依赖清单是 B 类件的唯一索引；两者都不允许出现同一资产的双真相源。
