# 变更工单 · 知识主题二次合并与命名去重

## 1. 为什么

用户 2026-10-27 报障：知识主题视图里「有好多个重复名字的节点，比如『智能』，
当然放射出去的子节点不同」。

真库核查（`temp/topic_dup_probe.py`，只读，4,552 点 → 1,003 主题）：

| 观察 | 数字 |
|---|---|
| top 500 中的重名 | **35 个名字、覆盖 96 簇**；`智能`×14、`agent`×10、`agent·推理`×4、`mcp`×3、`grpo`×3… |
| 同名簇之间的质心余弦 | 182 对里 **66 对 ≥0.8**（最高 0.90），116 对在 0.6–0.8 |
| 命名机制 | `shared_words` 取 top2；只命中 1 个词时名字退化为单词（`智能`），于是多个簇同名 |

结论：**两层原因叠加**——0.72 单遍贪心把同一主题切成多块（主因），命名只用共享词
（1 词时无区分度）是放大器。只改名字是遮丑；只合并则仍会留下少量重名。

## 2. 契约变更

| 项 | 变更 | 兼容性 |
|---|---|---|
| `GET /api/graph/topics` | **新增可选** `merge`（bool，默认 true）、`merge_threshold`（float，默认 0.85，夹到 `[0.5, 0.99]`） | 不传即默认行为；显式 `merge=false` 退回 R11 口径 |
| 响应顶层 | **新增** `merge_threshold`、`merged_from`（合并前成簇数） | 纯新增字段 |
| 响应 `topics[]` | **新增** `merged`（该主题合并了几个原簇；1=未合并） | 纯新增字段 |
| `topics[].name` | 语义不变（仍是成员共享词，禁发明）；**格式变化**：2 词 `a·b`、1 词 `a（N 点）`、0 词 `主题（N 点）`；同一响应内保证唯一（重复加 ②③…） | 前端只当字符串显示；搜索/高亮按子串匹配 |
| `pipeline/graph_topics.py::topic_clusters` | 签名加 `merge: bool = True`、`merge_threshold: float = 0.85` | 内部函数，api.py 与测试调用 |
| 表结构 / 字段 / locator scheme / `SOURCE_TYPES` / `STATUSES` / `CONFIG_SCHEMA_KEYS` / 能力注册表 | **无** | canary 六项零漂移 |

## 3. 算法

1. **归簇不变**：沿用 `_greedy_clusters(vecs, 0.72)`；落单点仍不成主题（宁缺毋滥）。
2. **二次合并**：把已成形的簇按点数降序排列，逐个与已合并簇心做余弦；
   最高分 ≥ `merge_threshold` 就并入（簇心按点数加权更新），否则自立。
   - 用「贪心 + 已合并簇心」而非 union-find 单链：后者在 0.75 会把 1,013 簇压成 280、
     最大簇 1,910 点（链式粘连），贪心按规模优先可避免。
3. **命名**：`shared_words` 仍逐词验证（禁发明）；2 词拼 `a·b`；1 词补 `（N 点）`；
   0 词 `主题（N 点）`；遍历时维护 `used` 集合，重名加圈号 ②③…。
4. **顺序**：先合并、再按点数排序、再截断、最后只给返回的 N 个主题命名（R11 的
   「命名是第二热点」结论照旧）。

## 4. 验证

- 真库 `/api/graph/topics?limit=80`：耗时、top80 重名数 = 0、`total` 与 `merged_from` 记录；
- 抽样 3 个合并簇人工核对是否同主题（`review` 式抽读）；
- `pytest tests/test_graph_topics.py`：新增合并、命名唯一、单词退化三例；
- 全量 pytest + canary；
- headless Edge 实测：主题视图搜索「智能」→ 命中高亮计数 > 0，Esc 清空。

## 5. 实施后数字

| 项 | 实施前（R11） | 实施后（R12） |
|---|---|---|
| 真库主题总数 | 1,003 | **934**（`merged_from=1003`，23 个主题发生过合并，最大 26 簇 / 113 点） |
| top 80 重名 | 35 个名字 / 96 簇 | **0** |
| 泛名（`主题（N 点）`）占 top80 | — | 0（命名取种子簇，避免合并后共享词变稀） |
| 端点耗时 | 2.69 s | **4.02 s**（多一遍合并；仍在 5 s 内） |
| 浏览器 | — | 搜索「智能」→ 257 / 779 节点命中（30 个主题），金框像素 3 → 1,944，Esc 复原 |
| 测试 | 659 passed / 1 skipped | **663 passed / 1 skipped**（新增 4 例），canary 零漂移 |

**实施中发现的一个坑**（已写进代码注释）：`_greedy_clusters` 的簇心是**成员均值**，
模长普遍 <1；直接点积会把余弦系统性压低——首版在 0.85 阈值下真库**零合并**、
测试却全绿（测试向量都是单位向量）。改成先投影单位球再比较后，
`total` 才按预期从 1,003 降到 934。
