# 变更工单：收录与源脱节（源消失不再归档）+ 本地源正文快照 + 三层去重自动化

- 日期：2026-10-30
- 触发：用户 2026-10-30 裁决——「删除数据源的文件不应影响 KnowAtlas 本身，被收录的内容和源应该脱节」；
  书签会失效、邮件/聊天记录/文件都可能被删，索引不能跟着消失。
- 用户同日选定范围：**A（状态脱节）+ B（本地源正文快照）+ C（自动去重）**；
  存量 82 条 archived **保持归档不复活**；点层语义去重（`dedup_points`）**不自动**，仍挂 `ksync --embed`。
- 关联：`变更工单-2026-10-19-契约返工.md`（H3 删除检测 / K1 同步不抓正文）、
  `变更工单-2026-10-27-fetch候选口径与定向补抓.md`、批次 68（pending 缓冲）、R16（重复版本清理）。

## 1. 现状与问题

### 1.1 源消失会把条目「藏起来」

`ksync --full` 走 `datalayer/entries.py::archive_missing`：本次未见且 active 的条目 → `status='archived'`。
`archived` 在 `_consumable` 与所有消费面（检索/词云/图谱/点召回/导出）按 `status='active'` 过滤，
于是**源侧删一个文件，库里就搜不到它了**——这正是用户要否定的语义。

### 1.2 正文没被收录

`fetch.on_sync=false`（K1）让同步只建条目不抓正文；真库 368 条里只有 77 条有正文副本。
本地文件源（folder）本来读一遍就免费，却也要用户手动 `--fetch-limit`，导致源删了正文永远没有。

### 1.3 去重只自动了一半

`dedupe_entries` 每轮对新/更新条目自动跑；**存量**要手动 `ksync --dedupe-scan`；
pending 转正后没有补跑去重。用户要求「当前三层去重自动」。

## 2. 方案

### 2.1 A：源存在性只进 meta，不再改 status

- 新增 `DataLayer.mark_source_state(source_type, seen_ids, run_id)`：
  - 本次全量遍历未见且 `status='active'` → `meta.source_state="missing"` + `meta.source_missing_at`；
  - 重新出现 → `json_remove` 两键（回到默认态）；
  - 只动 active，`pending/rejected/archived` 不参与；写一条 `task_log(action="source_missing")`。
- `pipeline/sync/__init__.py`：`--full` 默认改调 `mark_source_state`；
  **旧行为改为显式 `--prune-missing`**（`run_sync(prune_missing=True)`），仍走 `archive_missing`。
- 仅在 `full and limit is None and not entry_ids` 时标记（截断/定向不是完整遍历，不能判「源里没有」）。
- `stats`：`source_missing` / `source_cleared`；`archived` 键保留（默认 0），旧前端不炸。
- 存量 82 条 archived 不迁移、不复活（其中 74 条是 R16 故意清掉的重复版本）。

### 2.2 B：本地文件源同步时抓正文（正文快照）

- 新配置（**按源的子键**，不进 `CONFIG_SCHEMA_KEYS`，canary 不漂）：
  - `[sources.folders] snapshot_on_sync = true`（代码默认 folder=true，其他源=false）
  - `[sources.folders] snapshot_max_per_run = 50`（每轮补齐上限，防首次全库读爆）
- 在 `run_sync` 每源的 `upsert → pending 处置` 之后、`_categorize` 之前：
  1. 取该源 **active 且无 content_hash** 的条目（本轮新建的排最前），最多 `snapshot_max_per_run`；
  2. 调现成的 `_fetch_missing`（`file://` 走 `file_reader`，本地读，零网络费用）；
  3. 用刷新后的条目对象进分类——避免「空正文分类一次、抓到后再分类一次」的双重 LLM 费用。
- 网络源（bookmark/opml）默认不抓：仍受 K1 约束；转正后可由 `[ingest] enabled=true` 的巡检补抓。
- 只补「无正文」的条目；文件内容变化不自动重读（避免每轮全库重解析），需要时 `--entry` 定向重抓。

### 2.3 C：三层去重全自动

1. 条目 id 幂等、正文不重抓：本来就自动，不动。
2. 跨源 canonical / content_hash 合并：
   - `run_sync` 尾部（`sweep_rejections` 之前）自动 `scan_and_merge(dl, dry_run=dry_run)`；
   - `activate_pending` 与 Web「批量转正」之后对转正条目补跑 `dedupe_entries`。
3. 语义去重（点层 embedding + LLM 边界裁定）**不自动**：仍在 `ksync --embed`，避免每轮花钱。

## 5. 验证

1. 删除源文件 + `ksync --full`：条目仍 `active`、`meta.source_state=missing`、`search_fts` 仍命中；
2. 同场景 + `--prune-missing`：`archived`（旧行为可回退）；
3. 文件放回 + `--full`：`source_state` 键被清除；
4. 新文件不传 `--fetch-limit`：`content_hash` 非空、`content_store` 有全文，且分类用的是正文；
5. 两个同内容文件：自动合并（`dedupe_master`），`entry_locators` 附挂，可逆；
6. 全量 `pytest -o addopts= -q` 绿（基线 846 passed / 1 skipped）+ canary 零漂移 + `gen_docs --check` 三份 OK。

## 6. 风险与回滚

| 风险 | 处置 |
|---|---|
| 源临时不可达（网络盘掉线）被误标 missing | `source_state` 只是标记、不影响消费；根目录不存在时适配器直接 `AdapterError` 跳过，不标记 |
| 首次同步读大量本地文件变慢 | `snapshot_max_per_run`（默认 50）/轮；断点续跑，下轮继续 |
| 自动去重误并 | 沿用既有的「只标不删 + 两键可逆」；`dedupe_master`/`dedupe_reason` 置 None 即恢复 |
| 旧行为需要 | `--prune-missing` 保留 `archive_missing` 全路径 |
| 82 条历史归档 | 不迁移；需要时手动 `set_status(active)` 或后续加 `kaging --unarchive` |
