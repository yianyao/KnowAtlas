# 变更工单 · 点分诊落库与领域闸门（P0）

## 1. 为什么

勘误（P1）与老化（P2）要成为**常驻机制**，前提是先回答「这条知识点值不值得判对错/判过时」。
2026-10-25 全量实测（4,509 点）证明：只有约 35% 的点是**可判定的硬事实**，其余是观点与方法论（45%）、
特定系统内部实现/预测（20%）。不先分诊就开跑勘误/老化，等于拿真金白银去判「没有对错的东西」，
还会制造大量误报。

分诊结果必须**落库**而不是留在 `temp/`：`temp/` 可随时清空，结论要能被检索、被下游按 `kind` 过滤、
且对 P3 重抽后的同文本点自动继承（点以 `content_hash` 稳定）。

## 2. 契约变更

| 项 | 变更 | 说明 |
|---|---|---|
| `points.meta` | **新增 4 键** `kind` / `kind_why` / `kind_at` / `kind_model` | 不改表结构；取值见 §2.1 |
| CLI 子命令 `kpoints` | **新增参数** `--triage`、`--from-json PATH` | 接口签名变更，故立本工单；默认行为不变 |
| 能力注册表 | **新增 `point_triage`** | 与源无关的语义任务，注册在 `registry/builtins.py` |
| datalayer | 新增 3 个点查询方法 | 唯一碰 SQLite 的模块红线 |
| 表结构 / `SOURCE_TYPES` / `STATUSES` / locator scheme / `CONFIG_SCHEMA_KEYS` / REST | **无** | canary 常量不变 |

### 2.1 `meta.kind` 取值与语义（领域闸门）

| 值 | 含义 | 下游待遇 |
|---|---|---|
| `hard` | 可判定的硬事实：技术机制、API/代码行为、复杂度、协议与标准、数学定义、语言规范、算法性质 | **唯一**进入勘误（P1）与老化（P2）的集合 |
| `opinion` | 观点/主张/经验/方法论/价值判断 | 永不判对错、永不判过时 |
| `unjudgeable` | 特定系统内部实现细节、未来预测、脱离上下文无法核查 | 同上 |
| `dupe` | `meta.dupe_of` 非空的重复点 | 永不判；与消费面去重口径一致 |

`kind_why` 是分诊的一句话理由（≤200 字），`kind_at` 是写入时间（ISO8601），
`kind_model` 是产出来源：`seed:<文件名>`（导入既有分诊产物）或 LLM 模型名。

**保护说明**：这 4 个键是机器后处理结论，不属于源拥有的字段，故不在 `_SOURCE_FIELDS` 内；
`ksync` 的浅合并天然保留它们。`datalayer/db.py` 的 meta 浅合并注释处已登记，防止后人误加进 `_SOURCE_FIELDS`。

## 3. 实现

### 3.1 `src/knowatlas/semantic/tasks/point_triage.py`（新增）

- `SPEC = CapabilitySpec(name="point_triage", ...)`，输入 `items: list[dict]`（`point_id`/`text`），
  输出 `{kinds: {point_id: {kind, why}}, llm_used: bool, error: str}`。
- Prompt 沿用 `temp/errata_full.py::TRIAGE_SYS` 的三分诊口径（已实测 4,509 点、分布稳定）。
- 纪律：`ctx.llm is None` → `llm_used=False` 不抛；`LlmError` → 返回 `error` 不写库；
  非法 `kind` 值直接丢弃（宁漏勿错，不写半成品）。

### 3.2 `src/knowatlas/pipeline/triage.py`（新增）

- `is_hard(meta)` / `HARD_SQL`：领域闸门唯一出口，P1/P2 只准 import，不准各写一份 SQL。
- `run_point_triage(cfg, dl, *, limit=0, dry_run=False, seed_path=None, batch=30) -> dict`：
  1. 候选 = `kind` 为空且非 `dupe_of` 的点（`dl.points_without_kind`）；
  2. `seed_path` 命中 → 确定性写库（零 LLM 费），`kind_model="seed:<文件名>"`；
  3. 剩余候选 → 分批 LLM；LLM 不可用 → 整批 `{"skipped": ...}`、一个 meta 都不写；
  4. 写库走 `dl.merge_meta_of_point` + `dl.log_task(..., "triage", ...)` 留痕；`dry_run` 只报不写。
- 幂等：已写 `kind` 的永不重判，重跑 = 零写入。

### 3.3 `src/knowatlas/datalayer/db.py`（新增方法）

- `points_without_kind(limit=0, include_dupes=False) -> list[dict]`：`id`/`text`/`content_hash`。
- `point_kind_counts() -> dict`：验收 SQL 收进代码（`hard/opinion/unjudgeable/dupe/(none)`）。
- `points_of_kind(kind, limit=0) -> list[dict]`：P1/P2 的取数入口。

### 3.4 `src/knowatlas/cli.py`

`kpoints --triage [--from-json PATH] [--limit N] [--dry-run]`；与 `--purge-points`、`--retry-blocked`
互斥（同时给直接报错退出，不静默择一）。LLM 不可用返回退出码 3（`_EXIT_SKIP`）。

```powershell
uv run python -m knowatlas kpoints --triage --from-json temp/errata_full_triage.json --dry-run

```

## 5. 回滚

只新增 `meta` 键，零表结构改动：

```sql
UPDATE points SET meta = json_remove(meta, '$.kind', '$.kind_why', '$.kind_at', '$.kind_model');
```

实跑前把 `data/knowledge.db` 复制到 `temp/` 备份；`kpoints --triage` 本身可反复重跑。
