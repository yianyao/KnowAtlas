# 方案 · 四个大文件拆分（路线 A，2026-10-27 定稿）

> 决策：用户 2026-10-27 采纳「路线 A：只拆四个大文件，行为不变，canary + 全量测试兜底」，
> 并采纳三级工具策略（见 `ADR-2026-10-27-工具分级与边界.md`）。
>
> 四个文件合计 6,550 非空行，占 `src/knowatlas` 的 40%。拆完目标：**没有超过 800 行的
> 单文件，职责一眼可见**，但 URL、CLI 参数、公开方法签名、SQL 逐字不变。

## 0. 先立护栏（不立护栏不搬代码）

拆分是"纯搬家"，所以验收口径必须是**搬家前后完全等价**。四道护栏，全部先落地：

| 护栏 | 内容 | 失败时的意义 |
|---|---|---|
| `tests/test_web_routes.py` | 快照 71 个 `(method, path)` 对，断言集合完全相等 | 路由漏搬/前缀改错 |
| `tests/test_cli_surface.py` | `_COMMANDS` 键集合（13 个）+ `build_parser()` 解析结果快照 | 子命令或参数丢失 |
| `tests/test_datalayer_surface.py` | `DataLayer` 公开方法名集合（约 130 个） | 方法被顺带改名/删掉 |
| 既有 canary | DDL / config 键 / 能力指纹 | 契约被碰到 |

护栏本身零逻辑，只做集合比较；它们也是以后防"手滑重构"的常驻测试。

**共同纪律**（每一步都适用）：

1. 一次只拆一个文件，一个 commit；拆完立刻跑全量测试（约 45 s），不攒着跑。
2. 只搬不改：搬动时**逐字保留函数体、docstring、SQL 字符串**，方便 `git diff --color-moved` 审查。
3. 公开入口不变：`knowatlas.cli:main`、`knowatlas.pipeline.sync:run_sync`、
   `knowatlas.web.api:register_routes`、`DataLayer` 类名与构造签名全部保留（新模块只做 re-export）。
4. 依赖方向不变：routers 只能调 DataLayer 与 pipeline；mixin 只能碰 `self._conn`/`self._lock`。
5. 每步 `git revert` 可整体回退（一个 commit 一个文件）。

## 1. `cli.py` 775 行 → `knowatlas/cli/`（≈8 个文件）

最低风险：纯参数解析 + 薄命令壳，测试只依赖 `build_parser`。

```
src/knowatlas/cli/
├── __init__.py      # main() + _COMMANDS 注册表 + 共享 _open/_warn_if_llm_unavailable
├── parser.py        # build_parser()，13 个子命令的参数定义（纯 argparse）
├── cmd_entry.py     # kinit / kadd
├── cmd_sync.py      # ksync
├── cmd_points.py    # kpoints / kpoints --triage / kpeimport / kauto
├── cmd_quality.py   # kaging / kerrata
└── cmd_ops.py       # serve / kexport / kbackup / ktest / kcheck
```

- **搬**：14 个 `_cmd_*` 按域分组；`build_parser` 整体搬进 `parser.py`（不拆函数，只是换文件）。
- **留**：`_COMMANDS` 字典与 `main()` 留在 `__init__.py`，导入各 `_cmd_*`。
- **不改**：所有 `--flag` 名称、默认值、help 文案。
- 验收：`test_cli_surface.py` + 全量；再手跑 `python -m knowatlas kauto -h`。
- 工时：0.5 天。

## 2. `pipeline/sync.py` 782 行 → `pipeline/sync/`（≈5 个文件）

纯编排，无跨模块私有依赖，但被 `cli`/`ingest`/测试引用，必须保留 `pipeline.sync.run_sync` 路径。

```
src/knowatlas/pipeline/sync/
├── __init__.py      # run_sync 编排壳 + re-export（外部 import 路径不变）
├── fetch.py         # _fetch_candidates / _fetch_missing / _is_timeout / _clear_stale_fetch_flags
├── store.py         # _apply_content / _store_bodies / _ingest_content / _clean_options
├── enrich.py        # _categorize / _reclassify_all / _value_scan / _freshness_scan
└── flags.py         # _now_iso / _flag_value（小工具）
```

- **搬**：上表函数逐个搬，`run_sync` 里的循环体保留在 `__init__.py`，只把调用点改成
  `from .fetch import _fetch_missing` 等（相对导入）。
- **不改**：`run_sync` 的签名与返回统计键（前端与测试都依赖）；`_fetch_missing` 的
  `fetched_ids` 约定（`ingest.py` 在用）。
- 验收：`test_folders/bookmarks/emmx/maildir/entry_targeted/reject_prune` + 全量。
- 工时：0.5 天。

## 3. `web/api.py` 1,799 行 → `web/ctx.py` + `web/routers/`（9 个文件）

71 个端点全在一个 `register_routes` 里，互相共享闭包变量（`cfg/dl/locators/semantics`）。
拆法：把闭包变量收进一个上下文对象，路由函数签名不变。

```
src/knowatlas/web/
├── ctx.py           # @dataclass AppCtx(cfg, dl, locators, semantics, token_fp)
├── serializers.py   # 条目/点/线程的 dict 化（目前散在 handler 里的 *_payload）
├── routers/
│   ├── entries.py       # 23 条 entries + pending/rejected/not-knowledge/dead-links/uncategorized（≈6）
│   ├── threads.py       # 11 条 threads + threads-lookup + entry_threads/entry_summary
│   ├── graph.py         # 7 条 graph + tree（子图/径向/反查/预取）
│   ├── categories.py    # 5 条 categories + category_entries/rename/merge/uncategorized
│   ├── knowledge.py     # points / errata(2) / synthesize(2) / recall / freshness
│   ├── discovery.py     # search / sets / timeline / stats / cloud
│   └── admin.py         # sources / session / token-hint / mcp(3)
└── api.py           # 只剩 register_routes façade：建 ctx → include_router × 7
```

- **搬**：每个 handler 变成 `def handler(ctx: AppCtx, ...)`；`@app.get("/api/x")` 改成
  `@router.get("/x")` + `include_router(router, prefix="/api")`。
- **难点**：`_synth_items`、`_topics_cached`、`_file_response`、`_port_of` 这类被多处用的助手 →
  进 `serializers.py` 或 `ctx.py`；`install_security_middleware` / `check_write_access` 原样留在
  `api.py`（安全逻辑不参与拆分）。
- **不改**：URL 逐字、请求/响应 JSON 结构、写操作的三件套校验。
- 验收：`test_web_api.py`（27 例）+ `test_web_routes.py` 快照 + 手点首页/图谱/点详情。
- 工时：1 天。

## 4. `datalayer/db.py` 3,194 行 → `datalayer/`（10 个文件，契约区，最后做）

按表分 mixin，`DataLayer` 只做组合。**SQL 逐字搬运**，canary 的 DDL 指纹不动。

```
src/knowatlas/datalayer/
├── core.py        # __init__/close/transaction/init_schema/_guard + 连接与 PRAGMA
├── entries.py     # upsert/get/find_by_*/attach_locator/merge_entries/set_status/status_map/
│                  #   activation_times/archive_missing/list_entries/count_entries/merge_meta/
│                  #   list_by_*/get_entry_detail/entries_by_host/get_entries_by_ids/purge_source
├── categories.py  # create/rename/get/all_dag/all_category_paths/move/merge/attach_parent/
│                  #   attach_category/detach_category/get_entry_categories/category_names/…
├── points.py      # put_point/count_points/points_of_kind/points_without_kind/kind_counts/
│                  #   set_point_aging/list_points/point_sources_*/points_of_entries/purge_points/…
├── graph.py       # get_graph_data/overview/subtree/search_graph/radiate/reverse_reach/get_tree
├── threads.py     # create_thread/…/thread_items/conv_messages/threads_for_entry
├── vectors.py     # put_vectors/get_vector/all_vectors/… + point_vectors 系列
├── content.py     # put_content/get_content/get_content_preview/gc_orphan_contents/vacuum_into
├── search.py      # search_fts/search_entries_direct/search/get_point_hit/get_stats
└── ops.py         # log_task/get_task_log/start_run/finish_run/recent_runs/regress_cases
```

**关键坑（必须一起改）**：现在 `__init__` 用

```python
for name, fn in vars(type(self)).items():   # 只扫本类
```

把公开方法包了 `functools.partial(self._guard, fn)`。改成 mixin 后 `vars(type(self))` 看不到父类方法，
**锁会静默失效**（并发测试不一定抓得住）。正确写法：遍历 `type(self).__mro__[:-1]` 的 `vars()`
并按 `name` 去重；同时加一条测试 `_datalayer_methods_are_guarded`：随机抽 3 个公开方法，
断言调用时 `self._lock` 被持有（用 `threading.RLock` 计数或 `_is_owned()` 断言）。

- **不改**：方法名、参数、返回结构、SQL 字符串、事务边界。
- 验收：canary 零漂移 + `test_datalayer.py`（35 例）+ 全量 + `grep -rn "sqlite3.connect" src/`
  只命中 `datalayer/core.py`。
- 工时：1.5–2 天（先搬 entries/points 两块验证 mixin 机制，再批量搬其余）。

## 5. 顺序、工时与回滚

| 步 | 文件 | 拆成 | 工时 | 风险 | 回滚 |
|---|---|---|---|---|---|
| 0 | — | 四道护栏测试 | 0.5 天 | 无 | — |
| 1 | `cli.py` | `cli/` 7 文件 | 0.5 天 | 低 | `git revert <sha>` |
| 2 | `sync.py` | `sync/` 5 文件 | 0.5 天 | 中（`_fetch_missing` 契约） | 同上 |
| 3 | `api.py` | `ctx` + 7 routers | 1 天 | 中（URL 必须逐字） | 同上 |
| 4 | `db.py` | 10 文件 + mixin | 1.5–2 天 | 高（锁 + SQL） | 同上 |

合计 **4–4.5 个工作日**。每步一个 commit，push 后再进下一步。

## 6. 拆完之后（不在本方案内，但顺手可做）

- `cli/` 里每个子命令顺手补 `--help` 的一句"需要什么前置条件"（现在 help 只有用法）。
- `routers/` 每个文件顶部写「本域端点清单 + 依赖的表」两行注释，作为活文档。
- `datalayer/` 拆完后，`docs/模块地图.md` 的"重构视角"表要更新（届时它已被推翻）。
- 若后端后续要换 PostgreSQL：`core.py` 是唯一连接点，`entries.py` 等按表分文件后，
  方言差异可以集中在 `core.py` 的 SQL 适配层——这是拆分带来的**额外收益**，不是目标。

## 7. 明确不做

- 不重命名任何公开方法/URL/CLI 参数（改名是另一件事，需要单独工单 + 迁移脚本）。
- 不把 `DataLayer` 改成"每个表一个独立类互相调用"（那会引入 N 个对象、破坏单事务）；
  用 mixin 组合成**一个** `DataLayer`，事务仍只有一个。
- 不趁机把 SQL 搬到 ORM（SQLite 方言 + 现有 SQL 是资产，不是债）。
- 不在拆分 commit 里夹带任何行为变更/新功能。
