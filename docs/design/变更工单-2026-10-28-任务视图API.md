判据现状：`GET /api/stats` 已带 `recent_runs`（最近 5 条全量 `stats`），但没有按 kind 的最新一轮，
也没有未完成/试跑标记；页面上看不到「上一轮巡检在几点、抓了几条、错了几条」。

## 2. 方案

### 2.1 数据层（新增 1 个只读方法，不加表、不加索引）

`datalayer/ops.py`：

```python
def task_overview(self, recent: int = 10) -> dict[str, Any]
```

- 一条 `GROUP BY kind` 拿每类的 `runs` / `unfinished`（`finished_at IS NULL`）/ `last_at`，
  按 `last_at` 倒序；每类再取一行明细（`ORDER BY started_at DESC, id DESC LIMIT 1`，
  同秒并列时用 `id` 兜底，不靠行序）。
- 一条明细查询拿最近 `recent` 条（夹在 1–100）。
- 每行统一投影为
  `{id, kind, started_at, finished_at, duration_s, unfinished, dry_run, stats}`：
  `duration_s` 由 `_common._parse_iso` 相减（坏串/空值 → `None`，不抛），
  `dry_run` 从 `stats.dry_run` 透出，`unfinished = finished_at is None`。
- 返回 `{"kinds": [...], "recent": [...], "unfinished_total": N}`。
- 全部在一个锁持有期内完成（`_guard` 包公开方法），与 `get_stats` 同风格。

### 2.2 接口（新增 1 个只读端点）

`web/routers/admin.py`：`GET /api/tasks?recent=10`（`recent` 夹 1–100，缺省 10）。

- 响应 = `dl.task_overview(recent=recent)` 原样透出，字段见 §2.1；
- 只读语义与管理域其它 GET 一致：不要求 `X-KnowAtlas-Token`、不写库；
- 为什么新端点而不是塞进 `/api/stats`：`/api/stats` 被首页多次轮询（每次带全量 `recent_runs`），
  任务视图要按 kind 聚合、语义也会继续长（死队列/未完成），分开后互不影响。

### 2.3 前端（`index.html::mgmtData()`）

把「最近任务」徽标块换成任务卡片：

- 每类一行：`中文名` + `最后时间（YYYY-MM-DD HH:MM）` + `耗时` + `本轮条数（按类别白名单取键）`
  + 标记徽标（`试跑` / `未完成 N` / `错误 N`，其中未完成按该类历史轮次计数——最新一轮跑完
  不代表旧的被中断轮次可以静默） + `共 N 轮`；
- 类别中文名与计数字段在前端白名单（`TASK_LABEL` / `TASK_COUNTS`），未知 kind 退化为
  「kind + 错误数」，不因为后端新增任务类型而空白；
- 空库时给「还没有任务记录（跑一次 ksync / kauto 后可见）」的提示；
- 卡片随「数据管理」页签打开即拉取（与 `/api/sources`、`/api/stats` 并发），满足「跑完后
  打开页签 10 秒内可见、不翻日志」。

## 5. 明确不做

- 不加表、不加索引：`runs` 现量级（真库 61 行）扫表足够；将来真成瓶颈再按 `started_at` 建索引。
- 不在端点里读 `task_log` 明细：单条例子的审计链归 `get_task_log` / 条目详情，任务视图只答
  「上一轮跑了几条、错几条」。
- 不推送、不定时刷新：页面打开即拉取；自动推送属 `session-guard`/watcher 的职责。
- 不改 `finish_run` 的 `stats` 口径：`errors` 仍是计数（明细在日志与 `task_log`）。
