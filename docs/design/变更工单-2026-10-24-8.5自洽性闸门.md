# 变更工单 · TODO 8.5 知识点自洽性闸门

## 1. 要解决的问题（真实数字）

用户裁决（2026-10-24）把"点能不能独立读懂"升为点层验收标准：点必须是**带论据的观点/结论**、
**概念解释或术语描述**、**独立完整的步骤**、**独立数据**；只剩名词、一句干巴巴结论、被截断的
步骤都算不合格。样本验证当场抓到的两类具体病：

| 病症 | 实测证据 |
|---|---|
| 整篇照抄冒充点 | LLM 未连上时 18 个点全是 4,023 字整篇（R10 已加告警，但产物仍会入库） |
| 裸名词/残步骤没有守门 | 现有 `point_extract.run()` 只校验"text 非空"，`"JavaScript 数组"` 与"只有 2）3）两步"都会原样落库 |

`pipeline/points.py` 当前对 LLM 产出**零复核**：`len(text)>0` 即 `put_point`。生成层（prompt）
能降低概率，但 LLM 不保证；需要一层零费用、可回归的确定性守门。

## 2. 验收目标

1. 反例全部拦下：裸名词（`JavaScript 数组`）、步骤缺首步（`2）…`）、步骤跳号（`1）2）4）`）、
   步骤缺末步 / 省略号截断（`…`）、代码块未闭合、过短碎片。
2. 正例零误杀：真实库现有 **27 个点全部放行**（含 260 字十步流程点、短数据点、单句术语定义）。
3. 全拒条目不重复烧钱：记 `meta.points_gate` 后自动运行跳过；`kpoints --retry-blocked` 可重抽。
4. 点列表不出现"被拒点"：不合格点**不落库**（不污染检索/词云/关系图），审计留在 run stats + `task_log`。
5. 既有契约不变：`points`/`point_sources` 表结构、迁移版本、配置键集、REST 既有字段全部不动。

## 4. 判据（确定性规则，逐条给防误杀）

| 规则 | 判据 | 防误杀 |
|---|---|---|
| `too_short` | 去空白后长度 < **10** | 只拦空/碎片；"独立数据"通常 ≥12 字 |
| `bare_noun` | 无句末/分句标点、无数字、无代码块，且长度 < **40** | 有冒号、数字、代码、句号一律放行——宁漏勿误 |
| `steps_head_missing` | 步骤标记识别到 ≥2 个且最小序号 > 1 | 步骤标记必须出现在行首或 `；。：，` 之后，且数字后不能紧跟数字（防 `Gemini 3、` / `3.13` 误报） |
| `steps_gap` | 序号序列不连续（`1,2,4`） | 仅当 ≥2 个标记时才检查 |
| `steps_tail_missing` | 有步骤列表但结尾不是 `。！？；!?;` | 同上；单条编号（无列表）不检查 |
| `truncated_tail` | 结尾命中 `…` / `...` / `[截断]` / `（略）` / `此后省略` | 只认结尾，正文中间出现不判 |
| `code_fence_unclosed` | ` ``` ` 出现奇数次 | 无代码块不检查 |

**明确不判的两类**（无句法分析不可靠，交 prompt + Phase 8 人工抽检）：

- "只有一句干巴巴结论" vs "一句完整术语定义"——两者长度与标点完全相同，机器不可分；
- "指代不自足"（以"它/这/该"开头缺主语）——误杀风险高于收益。

阈值是模块常量（`MIN_POINT_CHARS=10`），不进配置：这是守门口径不是产品开关，少一个契约面。

## 5. 契约变更

| 契约 | 变化 | 影响面 |
|---|---|---|
| 表结构 / 迁移 | **无**（points、point_sources 不动，canary ddl 指纹不变） | 零迁移 |
| 条目 `meta` | 新增键 `points_gate = {"status":"blocked","reasons":{原因:计数},"at":ISO}`；重抽成功时**删键** | 只写 `entries.meta`，不影响消费面（消费面按 status） |
| `kpoints` 统计 | 新增 `points_rejected` / `gate_blocked` / `reject_reasons` / `rejected`（明细上限 20） | `runs.stats` 可查审计 |
| CLI | `kpoints --retry-blocked` | 新参数 |
| `point_extract` 能力 | `points` 允许为空数组（= 无可独立成点的知识）；版本 2.1.0，output_contract 注明 | 单测断言同步 |
| 配置键 | **无**；示例文件只加注释 | `CONFIG_SCHEMA_KEYS` 指纹不变 |
| REST | `/api/entries/{id}/form` 响应附加 `gate` | 既有字段不动，前端可忽略 |

**blocked 标记生命周期**（防死锁）：

- 自动运行：`_candidates` 跳过 `meta.points_gate` 的条目（不重复调 LLM）；
- `--retry-blocked`：清标记并重抽；Web 条目级"合/拆"（`entry_ids`）重抽前也清标记；
- `--purge-points` 语义不变（只清点层）；推倒重来后如需重抽被拦条目，用 `--retry-blocked`；
- 降级路径（LLM 未启用时的整篇照抄）**不过闸**：那不是"抽出来的点"，且 LLM 恢复后要允许重抽
  （否则长文 `…[截断]` 会被误判并永久阻断）。

## 6. 逻辑接线

```
point_extract.run() → 每个点 text
   → gate_point(text)                      # 零费用确定性复核
       ├─ ok    → 规范化 hash → put_point（一点多溯源照旧）
       └─ 不合格 → 丢弃 + stats 计数（不落库）
   → 若该条目 LLM 产出的点全部不合格 / LLM 明确返回 []：
       ├─ 非 dry-run：merge_meta(entry, {"points_gate": {...}})
       └─ 计入 gate_blocked，下次自动运行跳过
```

`stats["processed"]` 只计**产出合格点**的条目；整条被拦的计入 `gate_blocked`（不计 processed，
语义与 LLM 故障一致：没产出就不算处理完），`points_created` 只计合格点。`gate_blocked`
与 `points_rejected` 分开计，便于判断"是没抽出来还是被闸门拦了"。

条目 meta 的原因码除 7 个闸门原因外，多一个 `no_point`：LLM 明确返回空 `points`（原文
只有目录/名词/废话，确实没有可独立成点的知识），属"无点"不属"故障"。
