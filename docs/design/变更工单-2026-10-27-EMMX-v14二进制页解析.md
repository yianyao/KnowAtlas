# 变更工单 · EMMX v14 二进制页解析

## 1. 为什么

`8.7 万兴脑图接入验证` 一直挂账。现状实测（2026-10-27，真库）：

| 项 | 数字 |
|---|---|
| emmx 条目 | **1 条**（`43a1b524bc586b88`「重要概念」），`meta.degraded=true`、正文空、**0 点** |
| 磁盘上的 emmx | **2 个**：`重要概念.emmx`（26 KB / 4 页 / 8,897 字）、`文心V1.emmx`（3.3 MB / 4 页 / 61,795 字，含 26 张图，2026-10-27 19:22 新增） |
| 格式 | 两者均为 `Document Version="14.0.3"`、`DocVersion="13.1"`，`page/` 是空目录 |

即：**70k 字的高质量自洽笔记（JS 原型/作用域/闭包/箭头函数 + 文心方法）一个字都没进库**。
9.x 的 `page/page.xml` 解析路径完全正常，缺的只是 14.x 的二进制页。

## 2. 已取证的事实（只读，可复核）

zip 结构（两样本一致）：

```
document.xml(3 KB, 仅版面属性) / mmpage/page.bin + page-1/2/3.bin（正文二进制）
rels/page_formats.xml / theme.xml / mm.bkiwi(5976 B，两文件字节数相同) / media/*.png
```

`mmpage/*.bin` 的解码结论：

| 观察 | 证据 |
|---|---|
| 文本**未压缩**、UTF-8、**NUL 结尾** | `使用域\0`；88 个文本段中 77 个后面紧跟 `00` |
| **节点结束标记** = `00 00 00 0A 7F 00 00 00 0B 7F 00 00 00 00` | 按它切 page-1 得 **71 块**，块内文本语义连贯（如一块正好是「执行上下文 1/2/3/4」整段） |
| **节点内换行标记** = `00 00 00 01 7C 02 7B 04 01 02 7B 04` | 同一节点内多条内容靠它分介；page-1 命中 15 次 |
| 尾块四页完全一致 | `… 8B 01 D0 0F 8C 01 04 95 01 80 89 7A 00 00` |
| 页序 | `document.xml` 的 `<Pages V="page;page-1;page-2;page-3">`，首屏根文本分别是 `原型` / `作用域` / `闭包` / `箭头函数`（重要概念） |

规模（按块/字统计，`temp/probe_emmx_scale.py`）：

| 文件 | page.bin | page-1 | page-2 | page-3 | 合计 |
|---|---|---|---|---|---|
| 重要概念 | 102 块 / 4,379 字 | 71 / 2,298 | 72 / 1,865 | 15 / 355 | **260 块 / 8,897 字** |
| 文心V1 | 835 块 / 41,132 字 | 550 / 16,369 | 77 / 1,633 | 68 / 2,661 | **1,530 块 / 61,795 字** |

**已排除**（避免二次踩坑，`temp/probe_emmx_framing.py`）：

- 3 种字节对齐框架（`tag=byte`+varint、`tag=b>>1/type=b&1`、protobuf `b>>3`）：干净解析率 **4/71、5/71、1/71** → 不是 TLV/Protobuf/Kiwi 类结构；
- `08 <varint>` 不是唯一节点 id：71 块只有 **32 个唯一值**（106/394/390 反复出现），更像样式/引用号；
- 外部无可用资料：GitHub 全站仅 1 个 `mindmaster-xml-markdown` 仓库，自述「不含原生二进制解码」；grep.app 被安全校验挡住（2026-10-27）。

## 3. 契约变更

| 项 | 变更 | 兼容性 |
|---|---|---|
| 条目粒度 | emmx v14 **每页一条目**（原来：整文件一条降级条目） | `source_key` 从 `rel` → `rel#<page>`；旧文件级条目在 `ksync --full` 时按 `archive_missing` 归档（只标不删） |
| `locator` | `emmx://<rel>#<page>`（9.x 的 `#map` / `#file` 不变） | scheme 仍为 `emmx`，无新 scheme |
| `meta` 新键 | `emmx_format="v14"`、`page`、`blocks`、`hierarchy="flat"` | 仅 emmx 条目；`_SOURCE_FIELDS` 保护说明处登记 |
| 形态判定 | v14 **不调用 LLM 判定**（无树可判，省费用也免幻觉），按页整块入库 | `meta.judge` 不写；与 9.x 的 integral/split 并存互不影响 |
| 表结构 / `SOURCE_TYPES` / `STATUSES` / `CONFIG_SCHEMA_KEYS` / 接口签名 | **无** | canary 六项应零漂移 |

## 4. 方案

### A1（本期，确定性，零 LLM）

`adapters/emmx.py` 增加 v14 分支，接口不变：

1. `_bin_page_names(zf)`：按 `document.xml` 的 `Pages` 取页名（回退：`mmpage/*.bin` 排序），返回 `[(page_name, "mmpage/page.bin"), …]`。
2. `_split_blocks(bin_bytes)`：按 END 标记切块；丢掉无文本块（图片/边界框）。
3. `_block_lines(chunk)`：块内按「NUL 分隔 + BRK 标记」还原行；同一行被样式切碎的片段要拼回（重要：`提升只是…` + `出错，但如` 属同一行）。
4. `_parse_emmx_v14(...)`：每页一条目——`title` = 该页首个非空块首行；`inline_content` = 块之间空行、块内保留换行；`meta` 见 §3；正文 > 4,096 字走既有截断 + `content_hash` → `content_store` 全文（`_full_bodies`，与 9.x integral 同构）。
5. `_parse_emmx()` 入口分派：有 `page/page.xml` → 9.x 老路（不动）；否则有 `mmpage/*.bin` → v14 新路；都没有 → 现有降级。
6. `parse_tree()`（站内树形浏览）：v14 返回**一页一层**的扁平树（`{title, children: []}`），并带 `meta.hierarchy="flat"` 语义，不渲染假层级。

### A2（第二期，时间盒 1 天，可失败）

还原父子层级，目标让 `mind_path` / 树形浏览有真树：

- 已知块序应是 DFS（父块在子块之前），缺的是「深度或父 id」；
- 下一条路：在块内按「字段值 == 其他块某值」做配对搜索时先排除已证伪的 `08 varint`；再用两块样本（小图 260 块、大图 1,530 块）做一致性检验：抽 5 个已知语义父子（如 `作用域 → 全局/函数/对象作用域`）反查哪一列数值满足「子指向父且父唯一」；
- 若 1 天内找不到满足三条件的字段，**停手**，A1 交付不变，本单记录负结果。

### B（零代码备选，给用户）

若 A1 也不满意：在 MindMaster 里另存为 Markdown / PDF，走现成 folder / PDF 链路（层级与文本都在，代价是人工导出）。

### 明确不做

- 不改 9.x `page/page.xml` 路径与其测试；
- 不猜层级（宁缺勿错，与「宁整勿碎」同源）；
- 不动 `tools/kpe` / `kpeimport`；
- 不做「图片 OCR」（`media/*.png` 只记数量，不进正文）。

## 7. 实施记录（2026-10-27，A1 已落地）

用户裁决「批准 A1」（确定性页级扁平抽取，零 LLM）。落地时取证比立项时更细，三处与 §4 预案不同：

1. **文本段不是「NUL 分隔」，而是「标记定位」**：正文段以 `7B 04`（样式段）/ `01 04`（续段）/
   `14 ? 3F`（根节点，`?` 随样式变）开头；段与段之间的二进制字节会把「按 NUL 切」的抽取整段吃掉
   （实测只剩 `5priority` 这类样式名、正文全丢）。改为「标记定位 + 读到非法字节为止」后，
   `重要概念` page-1 的第 2 块完整还原成 8 行原文。
2. **换行判据**：段间前导含 `00 00 00 01 7C 02` = 作者换行；否则是**排版折行**，必须拼回同一行
   （否则「…才被设置。换」/「言之，变量」会被切成两行）。另加「间隔 > 128 字节 = 跨节点」
   兜底：根节点没有 END 标记，不兜底会把「作用域」和一级分支粘成一行（实测间隔 p99=66、最大 2,429）。
3. **页序顺带修了个 9.x 的老 bug**：`document.xml` 的页名在 `<Pages V="…">` 的**属性**里，
   原代码用 `findtext("Properties/Pages")` 取元素文本（永远是空串），一直靠「扫文件名兜底」。
   改成读属性后 9.x / 14.x 共用同一口径，回归全绿。

实际落地范围：

- `src/knowatlas/adapters/emmx.py`：`_bin_page_names` / `_split_blocks` / `_read_utf8` / `_text_runs` /
  `_block_lines` / `_parse_emmx_v14`；`_parse_emmx` 入口分派（有 `page.xml` 走 9.x 原路，没有则试 v14，
  都不行才降级）；`parse_tree` 返回一页一层扁平树（`hierarchy="flat"`，首块为根、子节点从第二块起，
  避免根重复）。
- `src/knowatlas/web/api.py`：`/api/entries/{id}/emmx_tree` 的锚点从「只认 `#map`」放宽到
  `#map` 或 `#page*`；v14 只回本条目那一页并重算 `node_count`（跨页串树会误导）。
- `src/knowatlas/web/static/index.html`：预览面板的门控同步放宽（`/#(map|page)/`）。

实测（2026-10-27 19:30，真库 + 真样本）：

| 项 | 数字 |
|---|---|
| 页级条目 | **8**（重要概念 4 + 文心V1 4），`degraded_files=0` |
| 块数 | 1,786（重要概念 260 / 文心V1 1,526） |

按 80 字节切多次重复计数；标记定位后每段只算一次，故数字变低但**内容更完整**（第 2 块 8 行可逐行对照）。
