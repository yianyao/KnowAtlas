## 1. 现状（2026-10-29 实测）

| 事实 | 证据 |
|---|---|
| 三页**都没有 `<meta name="viewport">`** | `index.html` / `graph.html` / `thread.html` 头部只有 `charset`；手机浏览器按 980 px 虚拟宽度渲染再缩，字小到不可用 |

| 分类树折叠态 `body.side-hide` 会连 `#tree` 一起 `display:none` | `components.css:72-77` → 手机抽屉要显式还原，否则抽屉是空的 |
| **没有 manifest / service worker / 图标 / favicon** | `static/` 只有 `*.html`、`*.css`、`ui.js`、`vendor/echarts.min.js`；`/favicon.ico` 实测 404 |

## 2. 方案

### 2.1 响应式（只动 CSS + 一个抽屉开关，不新建页面）

断点统一 **820 px**（手机横屏/小平板以下），560 px 再收一档。

| 层 | 做法 |
|---|---|
| 顶栏 | 高度 44 px、隐藏品牌字、搜索框吃满；新增 `☰` 钮（`.m-only`，桌面 `display:none`）开分类树抽屉 |
| 导航 | `#view-tabs` 由左竖排改为**底部标签条**（`position:fixed; inset:auto 0 0 0; height:54px; flex-direction:row`），`#layout` 补 `padding-bottom:54px` |
| 分类树 | `aside` 变**左侧抽屉**：`position:fixed` + `translateX(-102%)`，`body.side-open` 时滑入；配 `#side-mask` 遮罩；`side-hide` 的内联偏好不生效（显式还原 `#tree`/`.side-title`） |
| 预览面板 | 变**全屏浮层**（`inset:44px 0 54px`，`width:auto !important` 压掉内联宽），点条目即覆盖、`✕` 关闭；隐藏 `#pv-restore`（手机靠点条目重开） |
| 管理页 | `#mgmt-body` 横向可滚（表格式行不挤压），多选浮动条避开底部标签条 |
| 状态栏 | 手机隐藏（`host · 条目数` 价值低于屏幕高度）；离线提示改由顶栏小徽标承担（见 2.3） |
| `thread.html` | 300 px 侧栏改上下堆叠（`flex-direction:column`，侧栏 `max-height:45vh`），对话框限宽 `calc(100vw - 32px)` |
| `graph.html` | 头部已 `flex-wrap`，补窄屏内边距与字号；`100vh` → `100dvh` 兜底 |
| 三页 | 统一补 `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` |

### 2.2 PWA 壳（静态文件，零新增后端路由）

`app.py` 已把 `static/` 挂在根（`app.mount("/", _NoStoreHTML(...), html=True)`），因此
**放进 `static/` 的文件天然落在根路径**：`static/sw.js` → `/sw.js`（scope `/`）、
`static/manifest.webmanifest` → `/manifest.webmanifest`。**不加任何 FastAPI 路由**，
`tests/test_web_routes.py` 的 74 条路由快照不变。

| 文件 | 内容 |
|---|---|
| `static/manifest.webmanifest` | `name=知道 KnowAtlas`、`short_name=知道`、`start_url=/`、`scope=/`、`display=standalone`、深色 `background_color/theme_color`、192/512 图标 + `maskable`、`lang=zh-CN` |
| `static/sw.js` | 三类缓存策略（见 §2.3）+ 版本化缓存名 + 老缓存清理 |
| `static/icon-192.png` / `icon-512.png` / `apple-touch-icon.png` / `favicon.ico` | 由 `temp/gen_pwa_icons_20261029.py` 生成（Pillow，深底 + 强调色「知」），顺手消掉 `/favicon.ico` 404 |
| 三页 `<head>` | `manifest` 链接、`theme-color`、`apple-touch-icon`、`apple-mobile-web-app-*` |
| 三页 `</body>` 前 | SW 注册（5 行，`window.isSecureContext` 守门，失败静默） |

### 2.3 Service Worker 策略（离线只读，不碰写操作）

| 请求 | 策略 |
|---|---|
| `GET /api/**`（JSON） | **网络优先**，成功即写 `ka-v1-api`（上限 120 条，超出删最旧）；离线回落缓存；都没有 → `503 {offline:true}`（前端能显示「离线只读」而不是白屏） |
| `GET /api/entries/*/file` | **不进缓存**（原文代理可能是几十 MB 的 PDF），直通网络 |
| 四张 HTML 入口 | 网络优先 + 落 `ka-v1-shell`；离线回落缓存；再没有 → 内置离线说明页 |
| CSS / JS / `vendor/` / 图标 | stale-while-revalidate（先给缓存，后台更新） |
| 非 GET（所有写操作） | **完全不拦截**：直通网络。离线写会按既有 403/网络错误路径报错，不做静默排队（写操作三件套纪律） |

限制要写进文档，不夸大：**Service Worker 只在安全上下文生效**——`http://127.0.0.1`/`localhost`
或 https 可用；手机经 `http://192.168.x.x:8420` 访问时 SW 不注册（浏览器规则），此时
manifest 仍可「添加到主屏幕」并全屏启动，但**没有离线缓存**。真要手机离线，得先落 P2 反向代理 TLS。

### 2.4 离线可见性（前端）

`index.html` 状态栏旁/顶栏加一个 `.offline-badge`：`offline` 事件或首屏 `navigator.onLine === false`
时显示「离线只读」，`online` 时隐藏。目的是让「点写按钮失败」有解释，避免误判成 bug。

## 6. 已知限制

- 手机走 `http://<内网 IP>` 时 **SW 不注册**（非安全上下文）→ 只有「添加到主屏 + 全屏」，
  没有离线。要离线得先做 TODO P2 的反向代理 TLS。
- 离线缓存是**只读快照**：写操作在离线时一律失败（不排队、不静默），界面用「离线只读」徽标解释。
- API 缓存上限 120 条（LRU 近似：按写入顺序淘汰），故意不缓存 `/file` 原文代理。
- `vendor/echarts.min.js`（1 MB）在预缓存清单里；离线首次安装失败不阻塞（逐个 `add` 容忍失败）。
