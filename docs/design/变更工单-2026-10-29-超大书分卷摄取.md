## 2. 方案

### 2.1 新增 `pipeline/kpe_volumes.py`（纯规则 + 卷目录读写，零 LLM）

```python
@dataclass(frozen=True)
class Volume:                     # 一卷 = chunks.jsonl 里一段连续区间
    index: int                    # 1 起
    chunks: tuple[dict, ...]
    chars: int
    head: str                     # 首块的 section_path 首段（日志/审计用）
    @property
    def dirname(self) -> str: ...  # v001 / v002 …

def chapter_of(section_path: str) -> str
def pack_volumes(chunks, max_chars, *, min_fill=0.75) -> list[Volume]
def write_volumes(parent: Path, manifest: dict, volumes, *, book: str) -> list[Path]
def volume_complete(out_dir: Path, chunk_ids) -> bool
def volume_stats(out_dir: Path) -> dict          # chunks/done/points/complete
```

装箱规则（确定性、可测、可复现）：

1. 顺序遍历 chunks（保持阅读顺序），累计字符数；
2. `cur_chars + n > max_chars` → 必须切卷；
3. `章变了 && cur_chars >= max_chars * min_fill` → 优先在章边界切（不跨章硬塞）；
4. 单块本身 > 上限时独占一卷（KPE 的块本身受 `--max-chars` 约束，正常到不了这一步）；
5. **不重排、不丢块、不并块**：卷是 chunks 列表的连续区间，`Σ卷.chars == Σ块.chars`。

卷目录布局（`<entry>` = `data/kpe/<entry_id>/`）：

```
data/kpe/<entry>/
  manifest.json      # 整本（source/params/chunk_count）
  chunks.jsonl       # 整本切块结果（一次切好，PDF 的页码/章节路径都在这里）
  volumes.json       # 卷索引（max_chars / 每卷块数·字符数·首章·区间）
  v001/{manifest.json,chunks.jsonl,points.jsonl,done.jsonl,cache/,stats.json}
  v002/…
```

每卷的 `manifest.json` = 整本 manifest 的副本，`book` 改写为条目标题（进 `meta.book`），
追加 `volume` / `volumes` / `volume_chars` 三键；块 id **沿用整本的**（KPE 的 id 是
`sha1(section_path|index|text[:80])`），所以卷内 `done.jsonl` 与整本一一对应、可续跑。

### 2.2 `pipeline/kpe_runner.py::run_kpe_for_entry` 改为「先切块、再决定单卷/多卷」

1. 源文件解析不变（PDF 原件优先，解析不到才 dump `book.md`）；
2. **先跑一次 `chunks`**（本地免费、幂等）：`_chunks_ready()` 比对
   `manifest.source == src.resolve()` 与 `manifest.params.target_chars/max_chars`，
   命中就复用，不重复切；
3. `Σ chunk.chars <= kpe_max_chars` → **原单卷路径，行为逐字不变**（extract 一次 → 导入整本）；
4. 否则 `pack_volumes()` → `write_volumes()` → 逐卷：
   - 卷内 chunk 全部 done → **跳过 extract**（没有 LLM key 也能收尾）；
   - 否则按后端 failover 跑 `extract --retry-failed`（与单卷同口径）；
   - 每卷跑完就 `import_kpe_dir(..., entry_id=...)` 累加导入（点 hash 幂等）；
5. 某卷 extract 失败 → 先把该卷已产出的点导入，**停止后续卷**，返回 `status=error` 并带
   `volumes_done=k`；下一轮从该卷续跑（已 done 的块不再花钱）；
6. 返回统计**增量**加键：`mode`（`single`/`volumes`）、`volumes`、`volumes_done`、
   `volume_stats`；`chunks`/`points`/`out`/`source`/`llm` 语义不变（`chunks` = 整本块数）；
7. `dry_run=True`：**不切块、不调 LLM**。已有整本 chunks 时按当前配置报卷计划
   （`volumes` + `volume_plan`）；没有就只报 `would_chunk=true`。

### 2.3 `pipeline/ingest.py`：`meta.ingest` 多记两个键

`{"route":"kpe", …, "mode": res.get("mode"), "volumes": res.get("volumes")}`（只增不改）。

## 6. 已知遗留

- **PDF 取文偏少**：agentic-ai-guide 的 PDF 只有 871,299 字（正文 2,587,917 字，34%），
  按「PDF 优先」分卷只能覆盖该书的 34%；是否改成「正文更全就用正文」（会丢页码/章节路径）
  需另一条工单与对比数据，本轮不动（用户 2026-10-29 裁决）。
- 卷级并发：逐卷串行（卷内 KPE 自己 2 并发）。一本 2.6M 字的书 ≈ 5 卷 × 2–4 分钟，
  会占满一轮巡检；断点续跑可跨轮，暂不做卷级限速/预算。
- 换 `points.chunk_chars`/`points.max_per_chunk` 不会自动作废旧卷（块 id 与提示词都变了），
  需人工删 `data/kpe/<entry>/`。
